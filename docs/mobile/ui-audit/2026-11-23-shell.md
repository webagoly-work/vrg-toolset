# VRG Mobile UI audit: app shell and shared UI (static, read-only)

Scope: `Mobile/android/app/src/main/kotlin/hu/vrg/mobile/*.kt`, `kit/src/main/kotlin/hu/vrg/mobile/kit/**`, and
feature-settings, feature-account, feature-devices, feature-update and feature-pair. Checklist: `docs/mobile/UI-CHECKLIST.md`.
Paths below are relative to `Mobile/android/`.

**How the dp numbers were worked out.** The text-width figures are estimates. At 1.0 font scale, a 12 sp label takes about
6.6 dp per character and an 11 sp chip label about 6.2 dp. A Compose `Row` measures its fixed-size children first, in
order. Each one gets only the width still left over, and the `weight(1f)` children share whatever remains after that.
So once the fixed children run out of room, the later ones are measured at 0 dp: they are not drawn and cannot be
tapped. The phone is 360 dp wide; with the top strip's 2 x 8 dp padding that leaves 344 dp. `uiScale` (Beállítások,
range 0.8-1.3) multiplies the density, so at 1.3 the screen is effectively 277 dp wide. `targetSdk = 35`, so Android 15+
forces edge-to-edge drawing.

Already known and not reported here: the `faint` and `glowDim` colours fail contrast when used as text, and many texts
are 10 sp or smaller. The per-file counts are at the end.
