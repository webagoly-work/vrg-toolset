# VRG Mobile UI audit (link/PC/GitHub features): static Compose review against docs/mobile/UI-CHECKLIST.md

Scope: `src/main/kotlin` of feature-airdeck, -launch, -drop, -screen, -pcwin, -ports, -net, -claude, -inbox, -pulse, -notes, -apps,
-archive, -city, -stack, -sphere. Paths below are relative to `Mobile/android/`. Static reading only, no build or run.

Assumptions behind the dp budgets:
- Phone is 360x640 dp. The shell wraps each feature in `systemBarsPadding()` (ShellActivity.kt:116), which leaves about 568 dp
  of height upright and about 336 dp lying down.
- Text widths are estimated at about 0.55 em per character for `Melyviz.label`/`small` (11-12 sp) and 0.6 em for `readout` (mono).
- The UI size setting multiplies density (ShellActivity.kt:106). Any value above 1.0 shrinks the dp viewport, so every squeeze
  listed here gets worse with it.

Kit facts used throughout:
- `VrgChip` (kit/ui/Parts.kt:48) and Légegér's `Chip` (Controls.kt:133) draw 11 sp text with 5 dp vertical padding and no
  `minimumInteractiveComponentSize()`, so each one is about 25 dp tall.
- `DropdownMenu`/`RcoMenu` content scrolls (Material3 default), so RCO menus do not clip.
- `ModalBottomSheet` (Légegér `DeepSheet`) has `verticalScroll` and handles Back itself.

## Checked and fine

- WebView height: Apps, Archive and Stack set MATCH_PARENT.
- Popups: every `DropdownMenu`/`RcoMenu` scrolls.
- Sheets: Légegér's sheets scroll and their actions stay reachable.
- Sphere card: `heightIn(max = 72%)` + `verticalScroll` + `imePadding`.
- Lists: Inbox, Drop, Ports, Launch and Net use a scrolling `Column`.
- Pairing state: every relay feature has a Gate with "QR párosítás ›".
- Back: Apps steps back in WebView history, Stack exits full screen, Sphere closes its card.
