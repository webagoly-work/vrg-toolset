# M16 · Kit (`kit`): the VRG UI Kit's look on the phone

**State: BETA — built 2026-11-06 on H: (decisions 1A 2A 3A 4A 5A, see DECISIONS.md), waiting for the phone check
below.** M16 has no catalogue entry (it is a look, not a tile), so there is no stage to move in `Feature.kt`.

**Goal.** The phone and the desktop tools speak one visual language. The VRG UI Kit (`shared/vrg-ui-kit`, PR
webagoly-work/vrg-toolset#4) is HTML/CSS, so the phone takes its *tokens and rules*, not its code: the same colours,
type, the two temperatures (ice = you, warm = the system working) and the MINI. The app's own six palettes stay, and
so does its default.

## Shape

- **One source (2A).** `shared/vrg-ui-kit/tools/kotlin-tokens.js` reads `tokens/base.css` and the four theme files and
  writes `Mobile/android/kit/src/main/kotlin/hu/vrg/mobile/kit/theme/KitTokens.kt`: one `Palette` per kit theme (the
  existing `Palette` data class), mapped as below, plus the size tokens of the `touch` density (40 dp targets, 15 sp body).
  `--check` exits 1 when the file differs from what the tokens give; `mobile.cmd test` and the kit's `test/lint.js` run it.
  `color-mix()` tokens are resolved by the generator (sRGB mix over the theme's own surface), so Kotlin sees plain colours.

  | Palette field | Kit token |
  |---|---|
  | abyss · deep · surface · raised | `--vk-bg-sunken` · `--vk-bg` · `--vk-surface-1` · `--vk-surface-2` |
  | line · lineSoft | `--vk-line-strong` · `--vk-line` (resolved over `--vk-bg`) |
  | ink · muted · faint | `--vk-text` · `--vk-text-muted` · `--vk-text-faint` |
  | glow · glowDim · current | `--vk-accent` · `--vk-accent-line` · `--vk-info` |
  | sand · coral · kelp | `--vk-warn` · `--vk-crit` · `--vk-ok` |
  | onGlow · shallows | `--vk-text-on-accent` · `--vk-bg` |
  | (new) activity | `--vk-activity` — the warm "system working" colour, which the six palettes take from `sand` |

- **Palettes (1A).** `Palettes.ALL` grows to ten: the six as today, then `kit-ej`, `kit-papir`, `kit-kontraszt`,
  `kit-melyviz` (names Éj, Papír, Kontraszt, Mélyvíz (kit)). `Look.PALETTES` in kit-core gets the same ids in the same
  order (its test already checks that). The default stays `melyviz` (the app's own). A kit palette also switches the
  shape: radius from `--vk-radius-lg` (0 in Mélyvíz-kit), so `Melyviz.radius` becomes palette data.
- **Fonts (3A).** `kit/src/main/res/font/`: Inter 400/600, Barlow Condensed 600, JetBrains Mono 400 from the kit's
  `fonts/` folder (woff2 → ttf for Android, OFL, licence files in `kit/src/main/assets/licenses/`). `Melyviz.title` uses the
  condensed voice, `readout` the mono, body Inter. Only the kit palettes switch the faces, so the six keep their look.
  About +100 kB on the APK.
- **MINI (4A).** `kit/ui/Mini.kt`: `Mini(icon, label, state, progress, onClick, size)`. A ring (or 12 ticks) drawn with
  `Canvas`, states idle · running (determinate or a sweeping arc) · done (full ring + check corner) · error (notch) ·
  waiting (dashed) · paused · off; pressed = glow. `contentDescription` = "label — 42%" / "— kész" / "— hiba", as the web
  `VK.mini` writes `aria-label`. Animations stop with Android's "remove animations". Used on: the home tiles (a feature
  that is working shows its ring: notes outbox, update download, pulse refresh), Gyorsjegyzet's send, Frissítés chips.
  Targets ≥ 48 dp.
- **Kotlin purity.** The mapping table and the colour maths go in `kit-core` (`KitTokens` parsing test against the real
  token files), so the JVM-only test run covers them; `kit` only holds the generated Compose values and `Mini.kt`.

## As built (2026-11-06)

- `shared/vrg-ui-kit/tools/kotlin-tokens.js` → `kit/.../theme/KitTokens.kt` (`KitTokens.EJ · PAPIR · KONTRASZT · MELYVIZ`,
  `KitSize` = the touch density). Every translucent token (`--vk-line*`, `--vk-accent-line`) is composited over the
  theme's `--vk-bg`. `--check` runs in `mobile.cmd test` and in the kit's `test/lint.js`.
- `Palette` gained `activity` (default `sand`), `radius` / `radiusSmall` (default 14 / 10 dp) and `kitFaces`
  (default false), so the six palettes are byte-for-byte the same data. `Melyviz.radius` reads the palette.
- `kit-core/KitTokens.kt`: the same mapping and maths in Kotlin, plus `MiniState` / `MiniStatus` (the
  accessible sentence). `KitTokensTest` (6 tests) reads `shared/vrg-ui-kit/tokens` and the generated file.
- Fonts: `shared/vrg-ui-kit/tools/android-fonts.js` merges each face's latin + latin-ext woff2 into one TTF
  (`res/font/vk_*.ttf`, 4 files, 214 kB uncompressed; ő ű Ő Ű checked) with fonteditor-core (npm, not vendored; the
  script says how to run it). The woff2 subsets have no GPOS / kern table, so nothing is lost. OFL texts in
  `kit/src/main/assets/licenses/`, and a line under Beállítások → Névjegy.
- A kit palette switches the faces only (title Barlow Condensed SemiBold 0.06 em, body Inter, readouts JetBrains
  Mono); the sizes stay, so every screen keeps its layout on all ten.
- `kit/ui/Mini.kt` (+ `MiniTrack`): states as the web MINI, `contentDescription` = `MiniStatus.describe`, a still
  arc under "Animációk eltávolítása" (animator duration scale 0, read when the MINI first draws). `VrgFeature.activity`
  feeds the home tiles: Gyorsjegyzet (outbox send, with progress when several notes go), Frissítés (check, download %,
  error), Haladás (refresh). At rest a tile draws no ring at all. A busy `VrgChip(status = …)` gets a small ring:
  Gyorsjegyzet's Küldés and Frissítés, Frissítés's Keresés most and the download, and the Frissítés chips of Gömb and
  GitHub fiók.
