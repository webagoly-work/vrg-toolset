## Cél / Goal

A VRG Mobile a FunDo nélkül is beszéljen a Q71-gyel: idő, keresés mindkét irányba, állapot, időjárás, értesítések, mérések, és **saját számlapok**.
*VRG Mobile talks to the Q71 without FunDo: time, find both ways, status, weather, notifications, measurements, and our own watch faces.*

## Ami M61 óta változott / What changed since M61

| M61 said | Now known |
|---|---|
| "FunDo watches speak a closed protocol … nothing brand-specific is sent" | Fully decoded: GATT 18A0, RC4-wrapped MTK frames (130-byte default key), KCT text commands, notification XML, watch-face upload, .bin format. Encoder round-trips 45/45 captured frames byte-exact. |
| The Q71 is "paired in Android's Bluetooth settings" | On the Founder's Xiaomi it is **not bonded** (neither `64:C0:F9:A2:62:61` nor `CB:1C:7F:39:DD:60`); FunDo uses an **unbonded LE GATT link** to `Q71_LE`. So the M61 "paired device" path (presence, WatchRinger, Diagnosztika) never sees it. |
| Battery, notifications, find phone: "not possible" | Find phone, notifications, measurements: protocol known. Battery: probably a field of `GET,0` – unverified. |

## A protokoll röviden / Protocol in one screen

- **Link:** LE, unbonded, MTU 517. Watch service **18A0**: write **2AA1** (0x107, write with response); the watch notifies **2AA0** (0x105, no CCCD) with the ASCII doorbell `ios indication`, the phone then **reads 2AA0** until it returns empty. Standard extras: 1802 Immediate Alert (0x115 `02`/`00` rings the watch), 1803, 1804, FEE7.
- **The watch is also a GATT client of the phone:** it discovers the phone's server, writes the phone's **1802** to "find phone" (`02` start, `00` stop) and subscribes to the phone's **1805 Current Time**.
- **Frame:** `F0F0F0F1 | BE32 n | RC4(key, "<TYPE> <args>\0") | plain payload`, re-keyed per frame. Large frames span several ATT writes / reads.
- **Phone → watch:** `SYNC REQV` (→ `VERN 3`), `SYNC <unix> <tz ms>`, `EXCD KCT_PEDOMETER kct_pedometer 0 0 <len> ` + `GET,0` / `GET,10` / `SET,45,1|+01.0|<unix>` / `WEATHER;…` / `SETNEW,…`, `DATA <len>` + notification XML.
- **Watch → phone:** `EXCD <len>` + `KCT_PEDOMETER kct_pedometer 0 <n> RET,…` / `SEND,100–102` (measurement) / `SET,14` (camera) / `SET,43`, `SET,16` (unknown).
- **Watch face:** `SETNEW,1,<size>` → `RET,SETNEW,1,4096,1` → `SETNEW,2,<N>,<i>,<len>,<crc32>,<bytes>` per 4096-byte block, acked each. .bin = 64 B header + 0x80-byte element records + raw RGB565 frames.

## Kockázatok / Risks and limits

- **FunDo coexistence:** two apps on one link both read 2AA0 after the doorbell, so they steal each other's frames. Running both at once is not reliable (D-168).
- **Writes that could hurt the watch:** never send `MREE mre_installer …` (the watch's app installer) and never anything OTA-like; watch faces are data and a bad one is replaced by uploading another, but a cancelled / corrupt upload is tested before own faces (Q7 order).
- **Unknowns, kept unverified until tested:** battery field in `GET,0`; `SET,16`, `SET,43`; .bin header fields 0x10–0x2C, record +2 / +26; whether the watch checks the face id; the weather-code table.
- **The key:** MediaTek's built-in default from `libCommand.so`; firmware could in theory use another key – this watch does not.
- **Licences:** the protocol knowledge is ours; no FunDo code or assets are copied. The captured face (`watchface-pushed.bin`) is FunDo's: used only as a local test file, not shipped.
- **Privacy:** notification text exists only in transit to the watch; the raw captures in this folder contain one real notification and must not be shared.

## Döntések / Decisions (answered 2026-11-22, all the recommended option)

- **D-168 · FunDo:** **A** – VRG Mobile takes the watch over while it is linked; FunDo is stopped or uninstalled. (Both at once would steal each other's 2AA0 reads.)
- **D-169 · Home:** **B** – a new tile **Óra**. Tárgykereső's paired-device section links to it for the Q71.
- **D-170 · First round:** **A** – **Q0–Q3**: kct-core codec, link, basics (time, info, find watch, steps), find phone (GATT server). Q8 (Diagnosztika gap) may ride along as it is small.
- **D-171 · Watch faces:** **C** – PC first: `dial-bin.js` gets a writer (START menu entry), the phone only uploads; the in-app editor (Q7 Számlapszerkesztő) later.

Q7's home therefore moves: the upload step stays in the app (Óra tile), the face making starts on the PC.

## 1. kör: ami megépült / Round 1: what was built (Q0–Q3, D-170)

### Q0 · `kct-core` (pure JVM, `hu.vrg.mobile.kct`)

| File | What |
|---|---|
| `Frame.kt` | RC4 with the 130-byte MediaTek key; `Frame.encode / decode / payloadLength`; the **Reassembler**, a byte stream cut by the header's payload length (a frame over several reads, and one read that ends one frame and starts the next: both are in the capture), with resync after junk; `attChunks(mtu)` (ATT writes of at most 512 B). |
| `Kct.kt` | Builders: `syncRequest`, `syncTime(unix, tz ms)`, `setTime` (`SET,45,1\|+01.0\|<unix>`), `deviceInfo` (`GET,0`), `todaySteps` (`GET,10`), `findWatch` (`SET,40,x`), `ret`. The reply parser (`body`, `parse` → `Msg`); `DeviceInfo` (firmware, MAC, screen, profile, and the field before the MAC as an *unconfirmed* battery %); `Steps`; `Acky` (the watch's answer to SYNC: both its addresses and its name). **`isSafe`**: every outgoing frame passes it. Any `MREE` frame (the watch's app-installer channel) and anything named OTA / firmware / upgrade is refused. |
| `Session.kt` | One link's conversation as a state machine. Link up → `SYNC REQV`; `VERN` → the time (`SYNC` + `SET,45`), `GET,0`, `GET,10`; the answers FunDo gives (`RET,GET,10`, `RET,SET,43,1`, `RET,SET,14,1`); events for the screen (find phone, the watch rings, measurements kept for Q6). |
| `SetNew.kt` | The SETNEW block chunker (4096-byte blocks, `SETNEW,2,N,i,len,crc,` + the bytes) with the signed CRC-32, and the ack parsers. `NotifyXml` (escaped names, CDATA split at `]]>`) for Q5. |
| `Dial.kt` | The watch-face `.bin` reader, and a writer that puts it back byte-exact. By D-171 faces are made on the PC; the phone only reads and uploads them. |

FunDo's other start-up frames are left out on purpose: `EXCD language …` (en_GB), `MREE yahooweather`, `MREE mre_installer`,
`SET,15,1` and `SET,35,0,0` (meaning unknown).

### Q1–Q3 · `feature-watch`, the **Óra** tile (D-169: page 7 Egyéb, next to Tárgykereső)

- **Kapcsolat** (a switch): a `connectedDevice` foreground service (`WatchService`) while it is on, and only then.
  - It opens the phone's GATT server first, then the LE link to `Q71_LE` (`WatchLink`): the remembered address, or one
    20 s scan for the name.
  - **Never bonded**: `connectGatt` with `TRANSPORT_LE`, no `createBond`. MTU 517. On 18A0 it writes 2AA1, and after the
    2AA0 doorbell it reads 2AA0 until it is empty. One GATT operation at a time.
  - It reconnects with a back-off from 5 s to 5 min. The switch survives an app restart: it is the user's choice, kept
    in the prefs.
- **Idő**: set on every connect (`SYNC <unix> <tz ms>` + `SET,45`), and by *Idő beállítása most*. The phone's 1805 is
  notified too once the watch has subscribed.
- **Óra adatai** (`GET,0`, `ACKY`): the protocol version, firmware, screen, classic and BLE address and profile. The
  battery shows only as *feltételezés*.
- **Ma**: today's steps (`GET,10`), with *Frissítés*.
- **Óra keresése**: 1802 / 2A06 on the watch `02` + `SET,40,1`; **■ Állj** = `00` + `SET,40,0`.
- **Telefonkeresés** (`PhoneServer`): the phone's own GATT server with **1802 Immediate Alert** (2A06, write and write
  without response) and **1805 Current Time** (2A2B read + notify with a CCCD, 2A0F read).
  - A non-zero write rings the phone (`PhoneRing`): the alarm sound even on silent, vibration, and an alarm
    notification with **Megvan**; 60 s at most. `00` stops it.
  - The watch's `SET,40,1|0` on 18A0 counts as the same signal.
- **Tárgykereső** (D-169): its paired-device section and its watch panel say that the Q71 lives on the Óra tile, with
  **⌚ Óra megnyitása**. The old line *"a Q71 telefonkeresője csak a FunDo appal működik"* is gone.
- The Napló logs under the tag `watch`: frame headers only, never payload text.
- **Q8** (Diagnosztika for GATT-connected and non-Find-My devices) did **not** ride along in this round; it stays open.

### Tesztek / Tests

`gradlew :kct-core:test` (part of `Mobile\mobile.cmd test`): 19 tests.

- The fixture `kct-core/src/test/resources/q71-capture-b.txt` holds the 18A0 ATT values of capture b (2026-11-22
  11:03–11:07) in order. It is **redacted**: the weather place is replaced by `dummyplace` (same length), and this
  capture has no notification.
- All 23 phone frames decode and re-encode **byte-exact**. The 25 watch reads glue into 26 frames, and the whole
  watch → phone stream re-encodes byte-exact, also when it is fed one byte at a time. `GET,0`, `GET,10`, `SET,45`,
  `SYNC` and the `RET,…` frames built here equal FunDo's.
- The Session replays the capture: it sends what FunDo sent at the same moment, and answers what FunDo answered.
- SETNEW: 209 128 B → 52 blocks, the last 232 B; CRC-32(4096 × 00) = −954466287; the 4126-byte block's header. The CRC
  check value `123456789` → `CBF43926`.
- `.bin`: write → read → write is byte-exact on a synthetic face. With the captured face (on the PC only, never in the
  repo): `set Q71_FACE=…\hci-2026-11-22d\watchface-pushed.bin`, then `gradlew :kct-core:test`. Passed on 2026-11-22.

## Telefonon ellenőrizni (the Xiaomi and the Q71; FunDo force-stopped first)

1. **Óra → Engedélyezés**, then **Kapcsolat** on. The notification *Óra · Q71* appears, and the state goes *keresem az
   órát… → kapcsolódás… → kapcsolódva* within about 20 s. Napló `watch`: `found CB:1C:7F:39:DD:60`, `mtu 517`,
   `ready: 18A0 ok, 1802 ok`, `← VERN 3`. No pairing dialog appears, and the watch stays unpaired in Android's settings.
2. **Óra adatai**: firmware `XT2002D_AB024_Q71_T6_B_2104_V0.1_2111261102`, kijelző 240 × 240, BLE cím
   `CB:1C:7F:39:DD:60`.
3. **Idő**: set the watch's time wrong by hand, then switch Kapcsolat off and on: the watch shows the phone's time. Try
   *Idő beállítása most* too.
4. **Ma**: walk about 50 steps, then *Frissítés*: the number follows the watch's own count.
5. **Óra keresése**: the watch rings or vibrates, and **■ Állj** stops it. Dismiss it on the watch once too: does the
   button clear? Note what happens.
6. **Telefonkeresés**: start *find phone* from the watch's menu. The phone rings, on silent too, with the screen off and
   the app in the background. *Megvan*, the watch, or 60 s stops it. Napló: `phone server up (1802, 1805)`,
   `find phone from …: level 2`, and whether `1805 time subscribed` appears.
7. **Stays up for 10 minutes** with the screen off. Then walk out of range and back: *újrapróbálás hamarosan*, then
   *kapcsolódva* again by itself.
8. **Elem**: compare *elem: … % (feltételezés)* with the watch's own battery display at two different levels. If it
   follows, the `GET,0` field is the battery, and the *feltételezés* can go.
9. **FunDo afterwards**: Kapcsolat off, open FunDo: it still connects normally (nothing was left on the watch).
10. **Tárgykereső**: the Saját címke watch panel and the paired-device section show **⌚ Óra megnyitása**, and it opens
    the tile.
