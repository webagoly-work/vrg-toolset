# M21 · Alkalmazások (`apps`): the Desktop's HTML apps on the phone

**Goal.** The User-level in-shell apps of the Desktop open on the phone in a confined WebView, fetched from GitHub
`main`, changed files only, offline after the first fetch, each on its own https origin so `localStorage` works.
Map: `../PARITY.md` (units 9, 10, 12–17, 22). Built 2026-11-12, **BETA**.

## Build

- **Which apps, from the Desktop's own catalog.** `Mobile/catalogue/desk-gen.js` now also writes
  `kit-core/.../DeskApps.kt`: every `webapp` target of the User units, with the page and the folders the Desktop's
  `catalog.js appTarget()` gives it (the app's folder + `shared/`; a repo-root page alone). Eight apps: Varler Planner
  (Ügyfélnézet opens inside it, the same origin), Panel anyagár, Általános and LED kalkulátor, Készlet, Valena
  választó, VRG BuildTree, VRG MindMap. `mobile.cmd test` checks the file with `--check`; a webapp unit the Desktop
  cannot open as an in-repo app fails the generator.
- **What may be served: the Desktop's rules, ported** (`kit-core/.../Apps.kt`, `AppScheme.decide`): a port of
  `Dashboard/shell/lib/appscheme.js decide()`. Only the app's folders; `..` above the repo, drive letters, NTFS
  streams, names Windows would normalise (a trailing dot or space), dot-files and the secret names are refused; ports
  and user info are refused; the bare path serves the page. `AppsTest` mirrors `Dashboard/test/wp-43.test.js`'s
  decide cases on the phone's origins.
- **One https origin per app**: `https://<id>.appassets.androidplatform.net/` (the Desktop: `vrg-app://<id>/`),
  answered by the WebView's request intercept, so `localStorage` works and stays the app's own. **The app's saved
  data lives in that origin's storage on the phone; the origin must never change** (renaming an app id would lose it).
- **Files, like Archívum (M18)**: from `main` through the contents API with the M3 token. For each app the phone keeps
  its page, plus any allowed file the page later asks for, in `filesDir/apps/<id>/<repo path>` with a manifest of git
  blob shas. Opening an app (or ⟳) lists the folders of those files, then downloads only what changed (`.part`,
  size-checked, renamed) and drops what main dropped (`AppSync.decide`). Offline, the last copy opens. Today's apps are
  single files, so in practice only the page is fetched (the Planner 2.0 MB, Készlet 0.6 MB, the others under 0.2 MB).
  A file the page asks for that the phone does not keep yet is fetched once on the request thread.
- **The WebView**: JavaScript, DOM storage on; file and content access off; zoom allowed (pinch). A GET to the
  artifact CDNs goes to the network (Valena's Google Fonts); every other request off the app's origin gets an empty
  403 (the Planner's `127.0.0.1:8080/whoami` relay probes among them). A link that leaves the app opens in the phone's
  browser (also `mailto:` / `tel:`). `<input type=file>` opens the phone's document picker (Import buttons). Back steps
  back in the app's own history, then leaves it. JavaScript errors go to the VRG log.
- **The feature** (`feature-apps`): the list (state per app: on the phone with its size / offline / not downloaded yet,
  ⟳ mind), an app full screen under a thin header (‹, name, ⟳). The ◣ menu's web units and Kommand open the app
  straight (`vrg://apps/<id>`).
- **In Lapok (M20)**: a Desktop `cat:` web app resolves to the Desktop's own window kind `app` (`open = cat:<owner>`),
  so the picker offers the apps and the presets fill: Iroda brings the Planner (2 × 4; the calculator would overlap
  it), Készlet és árak brings Készlet (1 × 4). A full `app` window is the app itself in the sheet.

## Tests

`AppsTest` (9): the wp-43 decide cases (served, refused, Windows names, a repo-root page, sameApp), the generated list
against the catalog (every webapp target an app, every page in the repo and served), the sync rules (the page first,
only what changed, a cut download, a dropped file, offline, missing) and the paths / manifest. `SheetsTest` gained the
app window cases. 199 kit-core tests green, the APK builds.

`node Mobile/tests/apps-phone.js` (42 checks; `--shots <dir>` saves a screenshot per app, `--serve` runs the servers):
each app served with the phone's rules on its own origin, headless Chrome at 375 × 812 with touch. All 8 apps load
with no uncaught exception and no `console.error`.

## Telefonon ellenőrizni

1. Alkalmazások (tile, ◣ Munka → LED árkalkulátor, or Kommand „led”) → the list; LED árkalkulátor → it downloads
   (progress) and opens; the numbers react to − / +.
2. Change a price, leave with ‹, open again → the value is kept (`localStorage` on the app's own origin). Close the
   app completely, open again → still kept.
3. Varler Planner (2 MB) → downloads once; ⟳ afterwards says nothing new and is quick. The plan canvas draws; pinch
   zoom works.
4. Planner Projekt → Import (or Készlet / BuildTree Import) → the phone's file picker opens; a JSON file is read.
5. Flight mode → open an app that was downloaded → it opens from the phone („offline” in the list).
6. Valena választó → the fonts look like the PC's (CDN let through); a datasheet / outside link opens in the browser.
7. Lapok: + → Iroda → a sheet with the Planner; double tap its header → full; Back → its tile. Long press a free cell →
   „kalk” → a calculator window.
8. Back inside an app steps back in its own pages (if it has any), then leaves to the list.
