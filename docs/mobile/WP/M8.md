# M8 · Localhost (`ports`): the PC's local servers on the phone and on the desktop

**Goal.** The toolset starts many local servers: MindMap 8124, Inventory 8123, Kódváros live 8797,
Board Console 8790, CYD settings 8788 and more. The phone lists the ones running now. A tap opens one
**on the phone** or **on the PC in a separate app window**. D-10 = **C** (2026-11-05): both.

## Build

- **Relay** (paired phones only, M2):
  - `ports.list` → listening TCP ports on 127.0.0.1 / 0.0.0.0, read with `Get-NetTCPConnection -State Listen`
    on Windows and `ss -ltnp` elsewhere. Each port comes with its process name, the HTTP `<title>` from a 1-second
    probe, and a known name from `Mobile/catalogue/ports.json` (port → tool, kept beside tools.json).
  - `ports.open {port, path, where:'desktop'}` → opens `http://localhost:<port><path>` in a separate window.
    It uses the portable Chrome's `--app=` (`Full/tools/chrome`, else the system browser's new window).
    **Only localhost URLs**: the relay builds the URL itself from the port number, never from a string.
  - If D-10 includes the proxy: `/p/<port>/…` reverse-proxies to localhost for trusted phones, rewriting
    `Location` headers. Off unless the relay is started with `--ports`.
- `feature-ports`: a list with name, port, process, and a status dot. Buttons "📱 Itt" (WebView, or the browser
  through the proxy) and "🖥 A PC-n".

Node: the netstat / ss parsers on fixtures, URL construction refusing anything but ports 1–65535, the proxy

## Status (2026-11-05): BETA, built on H:, not yet on the phone

**What was built**

- **Relay** (`Planner/projects/varler-planner/tools/`): `relay-ports.js` (new: parsers, URL rules, the proxy
  gate, the probe, the desktop opener, the proxy) and `phone-relay-server.js` (the 5 Nov note at its top).
  - `ports.list` (trusted phone) → `{type:'ports', payload:{ok, took, ports:[{port, process, pid, http, status,
    title, known, id, path, system, self}], proxy:{on, token?}}}`. Probes run 24 at a time, one second each;
    on this PC 61 listening ports answer in about 2 s. Windows' own services (`svchost`, `lsass`, …) are
    flagged `system` and not probed.
  - `ports.open {port, path, where:'desktop'}` (trusted phone) → `ports.opened {ok, port, url, how}`. The URL
    is `http://localhost:<port><path>`, made from a port number (1–65535, a number, not a string) and a path
    that starts with one `/` and holds no space, `\`, `@` or control character; it is parsed again and must
    still be `localhost:<port>`. It opens in `H:\VRG\Full\tools\chrome\chrome.exe --app=<url>`, else the
    system browser through `rundll32 url.dll,FileProtocolHandler` (no `cmd.exe`, which would read `&` and `%`).
  - `/p/<port>/…` (only with `--ports`): a paired phone's `ports.list` answer carries a token (one per pairing,
    12 hours). The phone opens `http://<pc>:47291/p/<port>/<path>?vrg_t=<token>`; the relay turns the token
    into an HttpOnly cookie and redirects to the same address without it. Requests carry Host
    `localhost:<port>`, never the token cookie; `Location` headers pointing at localhost or at a root path are
    rewritten into `/p/<port>/`; a root-relative request from a proxied page (`/app.js`, seen by its Referer)
    is sent back under its `/p/<port>/`. Removing the pairing (on the PC or the phone) revokes the token at once.
  - `/whoami` reports `ports: true|false`.
- **Catalogue**: `Mobile/catalogue/ports.json`, generated by `node Mobile/catalogue/ports-gen.js` from START's
  `launcher/vrg-menu.json` servers (plus adb 5037). The test fails when it is out of date.
- **Phone**: `kit-core/Ports.kt` (the entry, its name / detail / status dot, the order, the proxy address, the

**What was decided while building (no question needed)**

- **netstat, not Get-NetTCPConnection.** `netstat -ano` + `tasklist /fo csv /nh` answer in ~100 ms; a
  PowerShell start costs a second or more. Listening rows are found by their zero foreign port, not the
  state word, which a Hungarian Windows prints as "FIGYELÉS".
- **A port bound to one LAN address only is left out**: it is not reachable as localhost.
- **"Itt" is a Custom Tab, not a WebView**: the proxy cookie lives in the browser, and a page works there as
  it does on the PC (downloads, file inputs). A WebView can come later if a tool needs to be inside the app.
- **The token is per pairing, 12 hours**, so a Custom Tab keeps working while the app's socket sleeps.

**What could not be verified here**

- No real window was opened by the tests (`RELAY_OPEN_DRY=1`); `chrome.exe --app=` was not watched opening.
- The release build (R8 / minify) was not built locally; Actions builds it on the push.
- `relay-e2e.js` did not run: Playwright is not installed in this checkout.
- **Known limits**: WebSockets inside a proxied page are not proxied (a page that live-updates over a socket,

  the relay's own phone page; all proxied tools share one origin on the phone, so they share localStorage.
