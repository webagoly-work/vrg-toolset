# M69 · Jegyzetek (`notes`): the central Notes app, with versions and origins

**Goal.** One central Notes app that users mainly work in, feature-rich and clean, with selectable **versions**
(module sets) in its settings, working as a **hub** other features write into, each note tagged by its origin so
notes from many places never get confusing. It replaces Gyorsjegyzet (M6), whose quick capture and day log
become modules of it. Asked by the Founder 2026-11-20; built the same day in a cloud session, **BETA**.
Decisions D-177 (phone first), D-178 (the private `vrg-notes` branch), D-179 (a linked mirror), all asked and
answered by the Founder. The contract for other features: `Notes/README.md`.

## As built

- **`Notes/catalog/noteskit.json`** (kind `vrg-noteskit`, data only, one source for the phone and the later Desktop
  page): 20 modules (5 core, 4 planned), 5 versions (Egyszerű, **Terepi** = default, Iroda, Fejlesztő, Teljes),
  7 note templates, 6 origins (kezi, gyors, megosztas, **sketcher**, and planned divergence / planner).
  `node Notes/tools/check.js` validates it; feature-notes' build copies it into the APK (`assets/notes/`).
- **kit-core `NoteHub.kt`** (pure JVM, `NoteHubTest`, 23 tests): the note `vrg-note` v1 and its JSON (local-only
  bookkeeping `unread`, `sha`, `dirty` never reaches the branch); `NotesKit` (parse, `enabled(profile, overrides)`:
  core always on, planned never, "*" = all; `problems`); `Notebook` (create, edit, tags, pin, archive, trash, purge
  to a tombstone, tasks, accent-free search, filters by view / tag / origin / book, pinned-first order, the daily
  note `d-YYYY-MM-DD`, templates with `{date}`, Markdown export); `NoteMirror` (the three-way linked mirror, see
  D-179); `NoteSync` (`vrg-notes`, `notes/<id>.json`, list → pull → conflict copy → sha-guarded writes, a file
  missing from the branch is written again, `rebase` keeps edits made while a round ran); `NoteContents` (the
  contents API's JSON; refuses any branch but `vrg-notes`).
- **kit `notes/Notes.kt`**: the hub every feature calls (`add`, `mirror`, `pull`, `onOpen`/`openSource`), the list in
  `files/notes/hub.json`, the version and module switches (prefs `notes-hub`). **kit `github/GitHubNoteHub.kt`**:
  the branch over the shared GitHub client.
- **`feature-notes`** (rewritten): the list (quick field, search, Mind / 📌 / ⇣ Beérkező / Archívum / Kuka, origin,
  book and tag chips, + Új, ☀ Mai, templates, rows or cards by version, origin badges, task counts); one note (title,
  body, Olvasó with headings / bold / code / tappable tasks, Teendők, Kód, 🎤, Megosztás, tags, Füzet, the origin
  box with "Megnyitás: Sketcher ›"); ⚙ (Változat cards with their modules, Modulok toggles, Szinkron, the origins
  with counts). The sync runs 4 s after a change, when the app comes on screen and through WorkManager. The M6 day
  log on `mobile-log` stays as the **Projektnapló** module (on in Fejlesztő): quick notes also go there.
- **The Sketcher (phone)**: `feature-sketch/ui/SketchNotes.kt`. Every Jegyzet entry is also note
  `sketcher-<survey>-<entry>` (label "<survey> · <room>", the quick chips as facts, ⚑ Tisztázandó as `open`),
  pushed after each save and on leaving the survey; texts edited in the app come into the survey when it opens; a
  deleted survey marks its notes `gone`. "Megnyitás: Sketcher" opens the survey on its Jegyzet front (`vrg://sketch?open=<id>&front=jegyzet`, F1's link).
- Catalogue `notes` → **Jegyzetek**, BETA, WP M69; its Katalógus page is rewritten. A share from another app is a
  note with origin Megosztás. CI also runs when `Notes/**` changes.

## Lezárás: client notes sealed (D-180, 2026-11-25)

- **kit-core `NoteSeal.kt`** (`NoteSealTest`, 10 tests): `NoteKey` (keys/<ID>.json, the Eszközök code), `NoteRecipient`,
  `NoteSeal.seal` / `open` (AES-256-GCM content key, wrapped per device with P-256 ECDH; additional data
  `vrg-note/1/<id>` and `vrg-note-key/1/<id>/<device>`; gzip inside, 2 MB cap), `NoteSeal.pin` (a key is trusted only
  when the code typed matches), `NoteCodec` / `SealCodec` (what the sync writes and reads: sealed when the note is
  `sealed` or of a `client` origin; a tombstone stays plain; no key → the note waits, never plain; a plain client file
  is rewritten sealed; a file for other devices is `Locked` and not fetched again).
- **`NoteHub.kt`**: `VNote.sealed`; templates may carry `seal` (`bejaras`, `ugyfelhivas`); mirrors of a client origin
  are sealed; conflict copies keep the flag; `Notebook.setSealed` (never off for a client origin), `Notebook.reseal`;
  commit messages name the note id only; `NoteSync.run(…, codec, locked)` reports `locked` and `waiting`.
- **kit `Notes`**: the codec from kit `Trust` (this device's id and key) and the pinned devices (prefs `notes-seal`,
  outside Git); `trust` / `untrust` reseal everything; `GitHubNoteHub.keys()` / `publish()` for keys/<ID>.json.
- **feature-notes**: the sync publishes this device's key once per start; 🔒 on sealed rows; the editor's
  🔒 Lezárás / Lezárva chip; ⚙ → **Lezárás**: this device's code, the sealed count, files on the branch for other
  devices only, the trusted devices (Megvonás), the other devices' keys with a code field and *Megbízom*.

### Telefonon ellenőrizni (Lezárás)

10. ⚙ → Lezárás shows "Ennek az eszköznek a kódja: XXXXXX". After a sync the branch has `keys/<ID>.json`.
11. A Sketcher note: its row shows 🔒; on GitHub, `notes/sketcher-…json` is `"kind": "vrg-note-sealed"` with no
    readable text, and the commit message is `vrg-notes: sketcher-… (lezárt) (<phone>)`.
12. A plain note: 🔓 Lezárás → its file becomes sealed at the next sync; 🔒 Lezárva → plain again. On a Sketcher note
    the chip only says it is always sealed.
13. Second phone, same account: its ⚙ → Lezárás counts the files it cannot open. On the first phone: ⚙ → Lezárás →
    the second phone in the list → type the code the second phone shows → Megbízom. After both sync, the second phone
    has the Sketcher notes. A wrong code says it does not match.

## What I could not verify here

- **The APK compile is Actions'** (`VRG Mobile (Android)`): the cloud sandbox runs only the JVM tests (kit-core
  288 and sketch-core 37 pass). The Compose screens, the hub's file and the GitHub calls were not run on Android.
- The contents API lists at most 1000 files per folder: past ~1000 notes the listing needs the git trees API.
- Sealing on a real phone: the Keystore-backed device key (kit `Trust`) was exercised only through kit-core's tests with
  JVM keys. What an earlier build pushed unsealed stays in the branch's history.
- The desktop Sketcher page (`Sketcher/dist/vrg-sketcher.html`) does not feed the hub yet (the Desktop Notes page
  is the next step, D-177).

## Telefonon ellenőrizni

1. Kezdőlap → Jegyzetek: "Teszt" tile. The list opens with the Terepi version: a quick field with 🎤, then search,
   view chips, + Új jegyzet and four template chips.
2. ⚙ → Változat → Egyszerű: the quick field, 🎤, templates and Beérkező disappear; the notes stay. Back to Terepi.
   Modulok: switch Füzetek on → "Füzet" appears in a note; "Vissza a változat moduljaira" switches it off.
3. + Új jegyzet: type a title and text with `- [ ] kábel`; Teendők shows it; tick it; the list row shows ☑ 1/1.
   ¶ Olvasó (Iroda or Teljes): headings and **bold** render, the task box ticks there too.
4. VRG Sketcher → a survey → Jegyzet: add a note in a room. Jegyzetek → ⇣ Beérkező shows it with the badge
   "◫ Sketcher · <survey> · <room>"; the Sketcher chip filters to it.
5. Edit that note's text in Jegyzetek → "Megnyitás: Sketcher ›" → the survey opens and its Jegyzet entry has the
   new text. Edit it in the Sketcher → the note in Jegyzetek follows.
6. Kukába → Kuka → Kuka ürítése: the note is gone and does not come back from the survey.
7. Signed in to GitHub: after a few seconds ⚙ → Szinkron shows "Vár: 0"; the repo's `vrg-notes` branch has
   `notes/<id>.json`. A second phone with the same account gets the notes.
8. Megosztás → VRG Mobile from another app: the text lands in the quick field; Mentés makes a note with the
   "⇣ Megosztás" badge.
9. Fejlesztő: a quick note also appears in `log/<today>.md` on `mobile-log` (Projektnapló).
