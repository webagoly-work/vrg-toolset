# M9 · Frissítés (`update`): the app updates itself from GitHub Releases

**Goal.** When a newer build exists, the app says so, downloads it and hands it to Android's
installer. The user confirms with one tap (Android requires that for apps outside a store). D-3 = A: GitHub Releases.

## User steps (the session cannot do them)

1. Create a release keystore **outside the repo** (`keytool -genkeypair -v -keystore vrg-mobile.jks -alias vrg
   -keyalg RSA -keysize 2048 -validity 10000`). Keep a backup: without it, no update can ever install over the
   current app again.
2. Add repo secrets: `MOBILE_KEYSTORE_B64` (base64 of the .jks), `MOBILE_KEYSTORE_PASS`, `MOBILE_KEY_ALIAS`, `MOBILE_KEY_PASS`.
3. One last time, uninstall the debug-signed app, because a different key cannot update it.

## Build

- `app/build.gradle.kts`: `versionCode` from env `VRG_VERSION_CODE` (CI: `git rev-list --count HEAD`),
  `versionName` `0.<wp>.<count>`, and the commit SHA into `BuildConfig.GIT_SHA`. A release `signingConfig`
  from env vars when present, else debug (local builds keep working).
- `.github/workflows/mobile-release.yml`: on a push to the chosen branch (main once PR #2 is merged; until then
  the PR branch) or manual dispatch, build `assembleRelease` signed and create a Release `mobile-v<code>`
  with the APK and `update.json` (`{code, name, sha, notes}` from the commit messages since the last tag).
- `kit-core`: version compare + `update.json` parsing, with tests.
- `feature-update`: checks on start (at most every 6 h) and from the tile. "Új verzió: 0.9.142 — mi változott"
  → download with the M3 token (a private repo's release asset needs `Accept: application/octet-stream`) → verify
  the size and SHA-256 from update.json → `PackageInstaller` session (`REQUEST_INSTALL_PACKAGES`).
- The home screen header shows a small "⟳ új" mark when an update is waiting.

## Tests (cloud)

Version compare, update.json parsing, the checksum check, the 6-hour throttle.
