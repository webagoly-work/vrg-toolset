# M5 · Kódváros online (`city`): the repo's city from GitHub

**Goal.** Kódváros on the phone, showing the **fresh GitHub state**. Only the online parts are shown: what is
in the repo on GitHub, never the PC's working copy or H:\. Answer D-7 first. The recommended default is A.

## Build (D-7 = A)

- **Actions**: `.github/workflows/mobile-city.yml`. On a push to any branch, it checks out the branch, runs
  `node CodeCity/scan.js . --out city.json --html city.html` (the same tool the e2e test uses), and publishes
  `city/<branch>/city.html` + `city.json` to an orphan branch `city-pages`. The commit uses `GITHUB_TOKEN` with
  `contents: write` on that one branch, and never touches the source branch.
  `scan.js` must not read anything outside the checkout. Check it, and note any gaps.
- `feature-city`: a branch picker (from M4's active list) and a WebView loading the city HTML from the raw
  contents API with the M3 token (a private repo cannot use public raw URLs). Download it to the app cache, then
  load it locally with JS on and file access confined. Offline: show the last downloaded city with its date.
- Touch: one finger orbit, two fingers pan / zoom. Kódváros's own input already handles touch, so check it
  and fix it in `CodeCity/src` if needed (that is a Kódváros change, so note it in docs/city as well).

## Tests (cloud)

The workflow script runs locally in the container (`node CodeCity/scan.js` on the checkout). The publish
step's path logic gets a unit test or a dry-run flag.

## Status (2026-11-06): BETA, built on H:, not yet on the phone, Actions not yet run

**What was built**

- **Actions**: `.github/workflows/mobile-city.yml`. On a push to any branch (not `city-pages`, `mobile-log`,
  `solomon-data`, which are data branches) it checks out the pushed commit with the whole history
  (`fetch-depth: 0`, the replay needs it), runs `Mobile/tests/city-publish.js`, fetches three.js into `Vendor/`
  (`node tools/fetch-vendor.js three`: `Vendor/` is gitignored and `CodeCity/build.js` inlines it; pinned with its
  sha512 in `vendor-manifest.json`), runs `node CodeCity/scan.js . --out $RUNNER_TEMP/city/city.json --html
  $RUNNER_TEMP/city/city.html`, and publishes with `Mobile/city/publish-city.js --push`. A **delete** event removes
  the deleted branch's city. `permissions: contents: write` (the job's `GITHUB_TOKEN`); every `${{ }}` value reaches
  a shell only through `env:`. One run per branch (`concurrency`, a newer push cancels an older scan of the same branch).
- **`Mobile/city/publish-city.js`** (new): writes city-pages with git plumbing only (`GIT_INDEX_FILE` on a temp
  index, `read-tree` of the current tip, `city/<key>/` replaced, `write-tree`, `commit-tree`), so the working tree,
  the index, HEAD and every source branch are never touched, and no `city-pages` branch is ever checked out. Layout:
  `README.md` + `city/<key>/{city.html, city.json, meta.json}`. `<key>` is the branch name as one URL-safe segment
  (`claude/m5` → `claude~2fm5`; [A-Za-z0-9_-] and a non-leading `.` stay, every other UTF-8 byte is `~xx`), so every
  branch is one folder, never nested, and the name comes back exactly. Without `--push` it is a dry run.
  - **Each publish is one root commit**, pushed with `--force-with-lease=refs/heads/city-pages:<the tip it read>`.
    A 1.4 MB page per push would otherwise pile up in the history every `git fetch` brings home. The lease is the
    one forced push in the toolset, limited to that generated branch; a publish that raced another one is refused,
    reads the new tip and retries (5×), so no branch's city is lost (the test makes that race happen).
  - It refuses `city-pages` itself, a missing city, a file that is not a Kódváros city, and anything over 95 MB
    (the raw contents API's limit is 100 MB).
- **Does `scan.js` read outside the checkout?** Checked: without `--sessions` (the workflow never passes it) it reads
  only `git ls-files` / `git log` of the checkout and the listed files; `build.js` reads `CodeCity/src`,
  `CodeCity/land.json`, `CodeCity/world.json` and `Vendor/three`, all inside the checkout. Gaps worth knowing:
  `world.json` is committed GitHub metadata about the vendored repos (public, already in the repo); git reads its
  own config as always, and nothing from it reaches the city. `--sessions` would read
  `~/.claude` transcripts, which is why the workflow does not pass it, and on a runner there are none anyway.
- **Phone**: `kit-core/City.kt` (`CityPages`: the key both ways, the contents paths, the branch list from the
  listing of `city/` with main first; `CityMeta`; `CitySync.decide`: Fresh / Download / Offline / Missing;
  `CityStore.prune`: the shown city plus the three most recently used are kept) and the new module `feature-city`
  (`CityFeature`):
  - The branch chips come from the **listing of `city/` on city-pages**, not from M4's active list: only a
    published branch has a city to show, and M4's list hides main and branches older than its window.
  - On opening (and ⟳) it asks for the chosen branch's `meta.json` through `GitHub.get` (ETag-cached: an unchanged
    city costs a 304) and downloads `city.html` only when the commit or the size differs, through the contents API
    with `Accept: application/vnd.github.raw` (kit `GitHub.download` gained an `accept` argument; the JSON answer
    stops at 1 MB). The download goes to `.part`, is checked against `meta.htmlBytes`, then renamed; the meta is
    written last. The MINI ring on the tile shows the download's progress.
  - The copies live in **`filesDir/city/<key>/`**, not the cache the WP named: Android may empty a cache, and the
    offline case is the point. Offline or signed out, the last city opens with "· offline" and its scan time.
  - **The WebView**: JavaScript and DOM storage on, file and content access off, zoom off, no cache. The page is
    served as `https://appassets.androidplatform.net/city/<key>/city.html` from `shouldInterceptRequest`, which
    answers that one file per key and gives every other request an empty 403 (the page's `/api/…` calls to the PC's
    Kódváros segéd, its `127.0.0.1:8134` trace ping, any other host). A real https origin also gives Kódváros a
    working `localStorage` (it fails on `file://`). Links to other sites open in the browser. Not interceptable: a
    WebSocket; Kódváros's 36-link tries `ws://127.0.0.1:<port>`, which on the phone is the phone itself and finds
    nothing. A crashed renderer (`onRenderProcessGone`) is dropped and reported instead of taking the app down.
  - **Touch, without changing `CodeCity/src`**: Kódváros's camera is mouse-made (left drag orbit, right drag pan,
    wheel zoom, click pick). `feature-city/src/main/assets/city-touch.js`, injected after each page load, takes the
    canvas's touch pointers in the capture phase and makes those gestures of them: one finger waits 6 px, then orbits,
    or lifts and picks; two fingers are a right drag at their midpoint plus wheel steps from the change in their
    distance (read once per frame, so a parallel drag never zooms); a still two-finger touch moves 4 px out and back
    so it never opens the context menu; a third finger, a finger that starts on a panel, and a cancelled touch are
    left alone. `CodeCity/src/03-scene.js` was not changed (another session has uncommitted work in it, and the
    adapter keeps the PC's mouse behaviour untouched); nothing to note in `docs/city`.
  - Catalogue stage PLANNED → **BETA**; `Registry`, `settings.gradle.kts`, `app/build.gradle.kts`.

**What could not be verified here**

  job's `GITHUB_TOKEN` may push `city-pages` (a branch protection rule or "Read repository contents" as the default

  reaches npm from the runner, and the run time (scan 5.5 s here; the checkout of the full history and the npm fetch

- The contents API with `application/vnd.github.raw` on the private repo was not called from here (no token in this

- Nothing ran on the phone: the WebView's WebGL on the phone's GPU, the frame rate of a 1 773-building city, memory
  (a renderer crash is caught, not prevented), the touch adapter with real fingers (tested with Chrome's touch input,
  not Android's), DOM storage on the `appassets` origin, links opening in the browser, the offline open, the prune.
- The delete-event path (`--remove`) is tested against the throwaway repo, not on GitHub.

  Run them as `node Mobile/tests/city-publish.js` and `node Mobile/tests/city-touch.js <city.html>`.

## Telefonon ellenőrizni

Előtte: a commit legyen fent a GitHubon (push), és a **VRG Mobile (Kódváros online)** Actions-futás legyen zöld
(github.com → Actions). A `city-pages` branchben legyen `city/main/city.html`.

- [ ] A kezdőlapon a **Kódváros online** csempe „Teszt” jelzésű, és megnyílik.
- [ ] GitHub belépéssel a main városa betöltődik és látszik (a sor: commit, idő UTC-ben, commitok és fájlok száma).
- [ ] WiFi-n az első betöltés 5 mp alatt van (a csempe MINI gyűrűje mutatja a letöltést).
- [ ] Egy ujj: forgatás. Két ujj széthúzva / összecsípve: nagyítás / kicsinyítés. Két ujj együtt húzva: mozgatás.
- [ ] Egy koppintás egy épületre kijelöli (a Kódváros panelje megnyílik), és a kamera nem ugrik el.
- [ ] Egy nyitott munka branche (pl. a PR #2 branche) is a chipek között van, és a városa betöltődik.
- [ ] ⟳ Frissítés változatlan városnál nem tölt le újra (azonnal kész).
- [ ] Repülőgép-üzemmódban újranyitva az utolsó város megnyílik „· offline” jelzéssel és a dátumával.
- [ ] Új push után (Actions zöld) ⟳ Frissítés az új commitot hozza.
