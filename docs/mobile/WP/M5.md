# M5 · Kódváros online (`city`): the repo's city from GitHub

**Goal.** Kódváros on the phone, showing the **fresh GitHub state**. Only the online parts are shown: what is
in the repo on GitHub, never the PC's working copy or H:\. Answer D-7 first. The recommended default is A.

## Build (D-7 = A)

- **Actions**: `.github/workflows/mobile-city.yml`. On a push to any branch, it checks out the branch, runs
  `node CodeCity/scan.js . --out city.json --html city.html` (the same tool the e2e test uses), and publishes
  `city/<branch>/city.html` + `city.json` to an orphan branch `city-pages`. The commit uses `GITHUB_TOKEN` with
  `contents: write` on that one branch, and never touches the source branch.
  `scan.js` must not read anything outside the checkout. Check it, and note any gaps.
- `feature-city`: a branch picker (from M4's active list) and a WebView loading the city HTML from the raw
  contents API with the M3 token (a private repo cannot use public raw URLs). Download it to the app cache, then
  load it locally with JS on and file access confined. Offline: show the last downloaded city with its date.
- Touch: one finger orbit, two fingers pan / zoom. Kódváros's own input already handles touch, so check it
  and fix it in `CodeCity/src` if needed (that is a Kódváros change, so note it in docs/city as well).

## Tests (cloud)

The workflow script runs locally in the container (`node CodeCity/scan.js` on the checkout). The publish
step's path logic gets a unit test or a dry-run flag.
