# M43 · VRG Térkép (`map`): the PC's map on the phone, with or without the PC

**Goal.** `Map/vrg-terkep.html` (served by `Map/serve.js`, port 8802 on the PC) on the phone, usable on site: the
Founder chose (2026-11-20) **D-48 = A**, a web app the M21 way with the PC's data through the relay when the PC is there
and the public planet files with a tile cache when it is not, and **D-49 = A + B + C**, the layers: the phone's position
and the Vázlat sites, the jobs (J) through the relay, Navigáció on a tap. Built in a cloud session, **BETA**.

Added 2026-11-19 with the paged home (WP M38, D-47); built 2026-11-20.

## Build

- **The page is the PC's, unchanged.** `feature-map` keeps `Map/vrg-terkep.html`, `Map/lib/geocode.js`,
  `Map/lib/jobs-layer.js` and `Map/style/terep.json` from GitHub `main` (contents API with the M3 token, git blob shas,
  only what changed: `AppSync` from M21) in `filesDir/map/page/`, and shows it on its own origin
  `https://map.appassets.androidplatform.net/` (the page's `localStorage` lives there; the origin must never change). The
  only change on the PC side: `window.vrgMap` now also carries `maplibregl`, for the phone's script.
- **The libraries** are not in Git (`Vendor/` is fetched). The phone downloads the same npm tarballs as
  `tools/fetch-vendor.js` (vendor-manifest.json: `maplibre-gl` 6.16.0, 6.2 MB; `pmtiles` 4.5.0, 0.1 MB) from
  registry.npmjs.org once, checks their **sha512 integrity**, and keeps the four files the page loads
  (`maplibre-gl.mjs`, `maplibre-gl-worker.mjs`, `maplibre-gl.css`, `pmtiles.js`; ~1.7 MB, BSD-3 notices inside).
  `MapPhoneTest` fails when the pins drift from vendor-manifest.json.
- **Every request is answered by the phone** (`shouldInterceptRequest`, rules in `kit-core/MapPhone.kt` `MapRoute`):
  the page files, the libraries, `/__phone/*` (the phone's script and the sites), `/data/*`, `/jobs/*`, `/remote/<host>/*`.
  Off the origin only what the page does on a tap may go out (Nominatim for "Keresés az interneten", the Google view
  G); the rest gets a 403.
- **Two ways to the data, chosen at each open** (the chip in the header says which):
  - **PC adat**: the paired PC's relay lists port 8802 (WP M8 `ports.list`, `--ports`) and the PC has
    `Map/data/hungary.pmtiles`. `/data/*` (offline Hungary, the address index) and `/jobs/*` go through `/p/8802/` with
    the page's Range header. The **public** parts read whole (`addresses.json`, its `manifest.json`, fonts, sprites) are
    kept in `filesDir/map/data/`, so the offline address search also works later on site.
  - **Internet**: no PC (or no data on it). The page runs in its own `?remote=1` mode: the Protomaps daily planet build
    and the Mapterhorn terrain are read with Range straight from their public servers; every answer is kept in a
    **400 MB tile cache** (`MapCache`: one file per URL + range, oldest-used out first), so a place looked at once opens
    again **offline**. Protomaps deletes old builds: once a day the phone checks that its build still answers and else
    moves to the newest one of the last three weeks (`MapBuilds`). A server's 412 (the file changed) drops that file's
    cached pieces.
  - **Offline**: neither; the cached pieces and the kept address index are what shows.
- **The phone's script** (`feature-map/src/main/assets/map-phone.js`, added before `</body>`): MapLibre's
  GeolocateControl (the position stays in the page; Android's location permission is asked on the first tap), the
  **Vázlat sites** as purple dots (read-only from the Sketcher's `filesDir/sketch/*.vsketch.json` via `sketch-core`;
  the card has Navigáció and Vázlat), and **Navigáció** on every job card. The keyboard hints are hidden.
- **D-31 / MAP-D2 on the phone.** The J layer's data comes through the relay only (so the PC's access log records it as
  `relay`, and its kill switch works at once); it is answered `no-store` and never written to the phone. Without the PC
  `/jobs/status` says "csak párosított PC-vel" and the button greys out. Navigáció hands the navigation app a `geo:`
  link with the **coordinates and the job code / sketch name only** (`MapNav`), never an address, and only on a tap.
- **Opening**: the home's Térkép tile (page 4), `vrg://map`, `vrg://map?job=BK2` (flies to the job, PC only). The map
  opens where it was left (the camera hash is kept). ⟳ re-checks GitHub, the PC and the build.

## Tests

`MapPhoneTest` (kit-core, 12): the page files exist in the repo and the page still exposes `window.vrgMap` with
`maplibregl`; the npm pins equal vendor-manifest.json; the remote hosts equal `Map/serve.js`'s; the routes (page, lib,
data, jobs, remote; `..`, encoded dots, dot-files, POST and foreign hosts refused); the page URL per mode, the job and
camera hash checks, the script injection; Range parsing; cache keys and eviction order; the build candidates; a tarball
(ustar + GNU long name) unpacked and its sha512 checked; the geo: link (label cleaned, outside Hungary refused); only the
tapped services may go out. `CatalogGuideTest` covers the new Katalógus page. `node --check` on `map-phone.js`.

**Not verified here (cloud session):** no Android SDK, so the module was compiled only by the "VRG Mobile (Android)"
Actions run (green on branch `m43-map`, run 69, 2026-11-20); no phone or emulator, so the real WebView (Range through `shouldInterceptRequest`, the module worker, WebGL), the
relay path, the GPS prompt and the navigation intent are checked on the phone (below). The proxy here blocks
build.protomaps.com, so the build check and the planet reads were not tried live; the npm tarballs and their integrity
were (registry.npmjs.org).

## Telefonon ellenőrizni

1. Kezdőlap 4. lap → **VRG Térkép** (a csempe „Teszt”). Első megnyitás GitHub belépéssel: „A térkép oldala a GitHubról…”,
   majd „Térképmotor: maplibre-gl 6.16.0…” → a térkép megjelenik (Budapest, döntve).
2. A PC-n **ne** fusson a térkép: a fejlécben **Internet**. Húzd, nagyíts, forgasd két ujjal; a 3D épületek és a
   domborzat (3D / Domb gombok) működnek.
3. Nézz meg egy helyet (pl. Budaörs), aztán **repülő üzemmód**, zárd be és nyisd újra az appot → a fejlécben **Offline**,
   és a megnézett hely ugyanúgy kirajzolódik (ami nem volt megnézve, üres).
4. A ◎ (saját hely) gomb → az Android engedélyt kér → elfogadva a kék pötty a helyeden; elutasítva rövid üzenet, a térkép
   megy tovább.
5. Egy Vázlatnál a Helyszín → „Itt vagyok (GPS)” → vissza a Térképre → **lila pötty** ott; koppintva a kártya a névvel;
   **Navigáció** → a navigációs app (Google Maps / OsmAnd) a ponttal nyílik, a címet nem kapja meg; **Vázlat** → a Sketcher.
6. A PC-n START → M (szerver H) és a relé `--ports`-szal (`Mobile\mobile.cmd relay`), a telefon párosítva → ⟳ → a
   fejlécben **PC adat**. Keresés: „Váci u. 12” → a találat a PC címjegyzékéből, odarepül.
7. Ugyanitt **Munkák** (J) → a piros ÜGYFÉLADAT jelzés, a tűk; egy tűre koppintva alul a kártya **Navigáció** gombbal →
   a navigációs app a munka kódjával és koordinátájával nyílik. A PC-n a `jobs\_elozmenyek\helyek-log.jsonl`-ban
   `"via":"relay"` sor van.
8. Kill switch: a PC-n hozd létre a `jobs\_elozmenyek\TERKEP-KI` fájlt → ⟳ a telefonon → a Munkák gomb szürke, a tűk
   eltűnnek. Töröld a fájlt.
9. Kapcsold le a PC-t (vagy a relét) → ⟳ → **Internet**; a Munkák gomb szürke („csak párosított PC-vel”), a keresés a
   PC-ről egyszer betöltött címjegyzékből továbbra is talál (címjegyzék: … cím).
10. „Keresés az interneten” sor a keresőben → csak koppintásra kérdezi a Nominatimot; gépelés közben nem.
11. **Árnyék** gomb (2026-11-21, `docs/map/SHADOWS.md`) → alul a panel: dátum, csúszka napkeltétől napnyugtáig,
    ▶ Napnyugtáig. Budapesten 16-os nagyítás felett az épületek árnyéka a nappal ellentétes oldalra esik, és
    a csúszkával forog; a ▶ lejátssza napnyugtáig. Repülő üzemmódban, egy már megnézett helyen is működik.
12. Hagyd el a térképet egy helyen, nyisd meg újra → ugyanott nyílik. A Katalógus 4. lapján a VRG Térkép oldala az új
    szöveggel, „Megnyitás” a térképre visz.
