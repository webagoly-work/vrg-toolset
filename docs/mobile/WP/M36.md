# M36 · iPhone: VRG Mobile as a web app (the online part), approved like any phone

**Goal.** The Founder, 2026-11-18: "will it work on another phone that is an iPhone 15?" — and the device approval and
updates "on that phone" the Proton Vault way. Answer and choice (asked, 2026-11-18): the APK cannot run on an iPhone,
so the iPhone gets **a web app with the subset that works in a browser** (option chosen over a native iOS app and
over Android-only). Built in a cloud session, **BETA**. Decisions D-42, D-43.

## What an iPhone can and cannot do here

| Works in the web app | Stays Android-only, and why |
|---|---|
| Eszköz: the device request QR and the grant (WP M35, same crypto) | Csipogó, Légegér: Safari has no Web Bluetooth at all |
| Haladás: commits, open PRs, CI runs on `main` | Képernyő, Átadás, Indítópult, PC ablakok: they need the PC's relay on the LAN, and an https page may not open `ws://` to a LAN address |
| Frissítés: a new web version, held back by the release lock | Hálózat: tethering and the phone's own relay are OS features |
| Megjelenés: the app's 11 palettes; the home-screen icon takes the chosen one | Notifications in the background: only once added to the home screen (iOS 16.4+), not built yet |

## As built (`Mobile/web/`, no build step)

- `index.html`, `css/app.css` (every colour a variable from `palettes.json`), `js/app.js` (dashboard with the faint
  Varler mark in the palette's glow, Eszköz, Haladás, Frissítés, Megjelenés), `js/device.js` (WebCrypto: a
  non-extractable P-256 key in IndexedDB, the `vrg-req` with its code and a `back` address, opening a `vrg-grant`;
  a token in it is kept in the page's storage), `js/qr.js` (the repo's own QR encoder, copied from Inventory with
  Project Nayuki's MIT notice), `sw.js` (cache-first: the app opens offline and changes only when *Frissítés most* is
  pressed, which the page allows only to an approved device while the release lock is on), `manifest.webmanifest`.
- **Generated, never edited:** `palettes.json`, `img/mark.svg`, `js/mark.js` come from `Mobile/catalogue/icon-gen.js`
  (the same palettes and mark as the Android icon, M34; `--check` covers them); `icons/touch-<palette>.png` (180 px,
  iOS ignores SVG) and `icons/icon-512.png` come from `Mobile/web/tools/icons.js` (Playwright).
- **The approval:** the iPhone shows its request QR; the owner's Android phone reads it (QR beolvasása), checks the
  code, approves; because the request carried the page's address, the grant QR is
  `https://…/mobile/#grant=…`: the iPhone's camera opens the web app with it and the grant is opened at once.
- **Published** by `.github/workflows/mobile-web.yml` on every push to `main` touching `Mobile/web/`: the browser test,
  then GitHub Pages at **https://webagoly-work.github.io/vrg-toolset/mobile/** with a `version.json` (`m36-<commit count>`).
- **Tests:** `Mobile/tests/web-app.js` (Playwright, iPhone 15 emulation, GitHub stubbed, 14 checks): the dashboard and its
  watermark colour (computed style), the palette switch and the touch icon, the request QR and code, a grant made the
  way the owner's phone makes it opened from `#grant=` (with the token), a grant for another device refused, the update
  offered to a listed device and held back for an unlisted one, Haladás, no console errors. The WebCrypto ↔ Kotlin match
  is `DeviceTrustTest.webCryptoAndTheAppAgree` (M35).

## The iPhone guide (2026-11-20)

The Founder asked for detailed written instructions wherever an iPhone is being connected. **One file,
`Mobile/web/guide/iphone.json`** (Hungarian), shown in both places so they never disagree:

- **On the iPhone:** a full page (`#/utmutato`), the dashboard's *iPhone csatlakoztatása* card while the iPhone is not
  approved, and the same guide folded open at the top of Eszköz until it is. Step 2 says whether the page is running
  in Safari or as the home-screen app (they keep separate storage), and each step is marked *az iPhone-on* or *a
  tulajdonos Android telefonján*. Eszköz also now reads the list every 10 s while waiting and says *Jóváhagyva!* by
  itself (the D-46 behaviour the Android phones already had).
- **On the owner's Android:** Eszközök → *iPhone csatlakoztatása*: a four-line summary, *Webapp QR* (the iPhone's
  camera opens the web app from it) and *Részletes útmutató* (the same file, bundled as kit's asset `iphone.json`;
  the owner's step opens first).
- The guide covers: what is needed, opening the web app, Safari vs home screen, the request, the owner's approval
  (scan = instant, a messenger request = code check), the automatic unlock (and why it can take 1–5 minutes), handing
  over the token and its risk, checking, and eight troubleshooting answers.
- Tests: kit-core `IphoneGuideTest` (the file parses, every step is there in order, the approval is the owner's, the
  buttons it names exist); `Mobile/tests/web-app.js` (22 checks now: the card, every section and step rendered,
  the Safari line, the guide open on Eszköz, the automatic unlock).

## One-time setup (the owner)

GitHub → the repo's **Settings → Pages → Build and deployment → Source: GitHub Actions**. Until then the deploy job
fails with "Pages not enabled" (the test job still runs). The site is public like the repo.

## Known limits

- **Home screen vs Safari.** An app added to the home screen keeps its own storage, apart from Safari. If the request
  was made in the home-screen app, the grant link the camera opens lands in Safari, which holds a different key: copy
  the message and paste it in the home-screen app (Eszköz → Engedély beillesztése). The page says so. Simplest: make
  the request where the app will be used.
- The service worker's cache and *Frissítés most* are not covered by the browser test (Playwright cannot stub
  requests that pass through a service worker): a phone check.
- A token handed over in a grant sits in the page's local storage: only grant it to your own iPhone (D-40 holds).
- Without a token GitHub allows 60 API calls an hour per network address; Haladás makes 3.

## Telefonon ellenőrizni (iPhone 15, Safari; the owner's Android with VRG Mobile M35)

1. Open https://webagoly-work.github.io/vrg-toolset/mobile/ — the dashboard, the faint bulb in the middle.
2. Megjelenés → Korallzátony → Share → *Add to Home Screen*: the icon is coral. Open it from the home screen.
3. Before approval the dashboard shows *iPhone csatlakoztatása*: the guide is readable and its step 2 names Safari or the home screen correctly.
4. Eszköz → *Kérés QR-kódja*; on the Android: QR beolvasása → approved at once; the iPhone says *Jóváhagyva!* by itself within a few minutes.
4. Read the grant QR with the iPhone's camera: if the request was made in Safari, Safari shows *Engedély elfogadva*;
   from the home-screen app, paste the shared message instead. Eszköz then says *Jóváhagyott eszköz*.
5. Haladás lists `main`'s commits and runs. Airplane mode → the app still opens (offline cache).
6. After a new push to `main`: Frissítés offers it; remove the iPhone from the list on the Android → it says the lock
   holds it back.
