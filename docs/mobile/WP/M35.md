# M35 · Eszközök (`devices`): phones let in by QR, the Proton Vault way

**Goal.** The Founder, 2026-11-18: authentication and release updates "like how we did it with Proton Vault: my
account, phone devices create the difference, and I allow the updates with QR codes". Built in a cloud session,
**BETA**. Decisions D-39 … D-41.

## Where it comes from

Proton Vault (`webagoly-work/data-vault`, `web/js/device.js`, `docs/PLAN.md` PV-D11 / PV-D12): every phone has an id
and a P-256 key; a phone without access sends a request (`pv-req`: id, model, name, a 6-character code, its public
key) by QR or messenger; the owner's phone checks the code by eye, adds the phone to `trust/devices.json` in the repo
and answers with a grant (`pv-grant`) that only that phone can open (ECDH + AES-GCM); `gated: true` makes the app
offer updates only to listed phones. VRG Mobile does the same, with VRG names (`vrg-req`, `vrg-grant`,
`Mobile/trust/devices.json`).

## As built

- **kit-core `DeviceTrust`** (pure JVM, `DeviceTrustTest`): JWK P-256 keys, the request with its code
  (SHA-256 over id + key, so a changed QR shows another code), the grant (the AES-GCM key is the raw ECDH secret,
  12-byte IV, 128-bit tag: WebCrypto's shape), capsules as base64url JSON in `vrg://devices?req=…` / `?grant=…` links
  (a web device's grant goes back to its own page as `…#grant=…`), reading a capsule out of a whole messenger
  message, and the trust list (`gated`, devices, add / remove, `updatesFor`). `Mobile/tests/device-trust-fixture.js`
  makes a request and a grant with Node's WebCrypto and the JVM test opens them both ways, so the iPhone web app
  (M36) and the Android app are proven to agree.
- **kit `Trust`**: this phone's id (the Access device code, so `access.json`'s owner code is the same id), its key
  (Keystore-backed store), its name, the cached list, `refresh()` (the public raw file, then the API with a token),
  and the owner's writes to `Mobile/trust/devices.json` on `main` through the contents API (`approve`, `setGated`,
  `remove`). A grant that carries a token is kept like a sign-in (`GitHub.adoptToken`).
- **`Access.locked` now also opens for a phone on the trusted list**: a new phone no longer waits for a release that
  lists it in `access.json`. The lock screen's first button is *Hozzáférés kérése ›* (Eszközök stays open while locked).
- **Frissítés** reads the list before deciding: with `gated` on and the phone not listed, it says so and points to
  Eszközök instead of offering the download.
- **`feature-devices`**: this phone (code, status, name), *Kérés QR-kódja* (QR + code + share), *Engedély beillesztése*;
  for the owner: *QR beolvasása ›* (the shell's scanner routes `vrg://devices?…` here), *Kérés beillesztése*, the request
  card with the big code, *A GitHub tokenem is* (off by default, see D-40), the grant QR, the list with *Eltávolítás*
  and *Kiadások zárolása*. QR codes are drawn with ZXing core (`kit/ui/QrCode.kt`).
- **`Mobile/trust/devices.json`** starts with the owner's Redmi (the `access.json` code) and `gated: true`.

## Known limits

- **The repo is public** (GitHub reports `webagoly-work/vrg-toolset` as public). The release lock therefore filters
  the in-app update only; the APK's download link stays open, as Proton Vault's own note says. Making the repo private
  turns it into a real lock (the repo-name access of `access.json` then ends by itself).
- The list is read from `raw.githubusercontent.com`, which caches for up to ~5 minutes: an approval can take that
  long to show on the other phone unless a grant QR is scanned (the grant opens at once).
- Writes from a granted phone are the owner's account; Proton Vault's per-device branches (`device/<id>`) are not
  copied yet: Gyorsjegyzet already writes to its own notes branch, never to `main`.

## Telefonon ellenőrizni (two phones; the owner signed in to GitHub)

1. Owner phone → Eszközök: status *Tulajdonos*, the list shows the Redmi, *Kiadások zárolása* on.
2. Second phone (a release build, not on `access.json`): the lock screen → *Hozzáférés kérése ›* → *Kérés QR-kódja*.
3. Owner phone: kezdőlap → QR beolvasása → the request card opens in Eszközök with the same 6-character code.
   Jóváhagyás (token off) → a grant QR. GitHub shows a commit on `Mobile/trust/devices.json`.
4. Second phone: read the grant QR with the camera app → Eszközök opens, *Engedély elfogadva*, the lock screen is gone.
5. Second phone → Frissítés: a new release is offered. Owner removes it from the list → Frissítés says the lock blocks it.
6. Token handover: repeat with *A GitHub tokenem is* on → the second phone's GitHub fiók shows the owner signed in.
7. A request sent by messenger: *Megosztás* → paste the whole message on the owner phone → *Kérés beillesztése* works.
