# M14 · Gömb (`sphere`): the three signals on the phone

**State: built 2026-11-01, LIVE since 2026-11-05 (the user: the swipe works).**

**Goal.** Swipe left from the home screen to a full page with the Solomon sphere: one dot per document, red where two
statements clash. Tap a dot to read its signals with their sources. The phone reads and rules; it never edits a source.

Rules and signals: `docs/solomon/README.md`. The look matches `Solomon/src/index.html` (SOL-Q1 = A).

## Shape

- `feature-sphere`, in the same pattern as `feature-pulse`: `SphereFeature.kt` (data, page, card, ruling) and `Disc.kt`
  (the canvas and its gestures). The rules are `kit-core`'s `Sphere.kt`.
- **Swipe:** a `HorizontalPager` in `ShellActivity`'s home route, page 0 `HomeScreen`, page 1 the sphere. Tiles and the
  back stack stay as they are. It also has a tile, for anyone who does not discover the swipe. The back button returns
  to page 0.
- **Inside the page:** three tabs as on the web page: Gömb, Jelzések, Szakaszok. They change by tapping, so a sideways
  swipe always means the home screen.
- **Data:** `Solomon/data/signals.json` and `rulings.jsonl` from the `solomon-data` branch (SOL-Q2 = B) through the M3
  client, on opening and at most hourly, or with the Frissítés chip. The last copy stays on disk and its date shows, so
  the page works offline.
- **Sphere:** a Compose `Canvas` with the same projection: the islands, ambient dots, pulsing pair, arc, sand ring and
  dotted ring. The placement formula is identical to the web page, so a dot sits in the same place on both.
- **Colours:** Mélyviz tokens, so the sphere follows the palette in Beállítások. `coral` stays the only red. A document
  changed in the last 7 days uses `current`, where the web page uses its warm accent.
- **Rotation:** a drag that starts inside the disc turns it and is consumed, so the pager never sees it; one that starts
  outside swipes the page. Slow idle spin, which stops while a card is open. Android's "remove animations" setting stops
  the spin and the pulse.
- **Ruling:** first / second / coexist with a required reason, on confirmed contradictions only. It appends a line to
  `Solomon/data/rulings.jsonl` on `solomon-data`, read + sha + write with a retry, as M6 does for notes. It has no outbox:
  offline it reports the failure and the reason stays in the box. `Contents.putBody` writes `mobile-log` and
  `solomon-data` and refuses every other branch. The phone never creates `solomon-data`.
- The PC takes the phone's rulings in on its next run, or when `Solomon/serve.js` starts.

## Check

Done here:
- `SphereTest` in `kit-core` (21 tests): parsing, placement and projection against values from the page's own code, the
  repository's real `signals.json`, rank and order, the ruling's append and retry.
- Debug and minified release APKs build.
- `tools/solomon.js publish` and `pull` against a throwaway remote: a phone ruling arrives once, a ruling landing between
  fetch and push survives, a client code stops the push, no link leaves the data in place.

**Telefonon ellenőrizni** (nothing above ran on a device; this PC has no phone on USB and no emulator):
1. A kezdőlapról balra húzva megjelenik a Gömb; jobbra húzva és a vissza gombbal visszatér.
2. A korongon belül indított húzás forgatja a gömböt, és nem lapoz. A korongon kívül indított húzás lapoz.
3. Egy pontra koppintva megnyílik a kártya; a piros pár (RB-L 41 W / 42 W) mindkét forrása olvasható.
4. A három jelmagyarázat-gomb szűri a pontokat, a Jelzések egy sora a gömbön a saját pontjára fordul.
5. Repülő módban a lap megnyílik az utolsó adattal és dátummal.
6. Egy döntés indoklással megjelenik a lapon, és a `solomon-data` branch `rulings.jsonl` fájljában is.
7. Sima a forgás, nem akad a 385 pont mellett.
