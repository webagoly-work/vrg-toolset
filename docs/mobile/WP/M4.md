# M4 · Haladás (`pulse`): the active branches, fresh

**Goal.** One screen answers "where does the work stand?". D-8 = A turned this round: every line of work lands on
`main`, so `main` comes first (last commits, CI, **which tools it changed in 7 days**), then a card only for a branch
ahead of `main` with a commit in the last 14 days, with its open PR. The tools are the toolset's
(`launcher/vrg-menu.json` plus the apps like VRG Mobile itself), each with its file count and the branches that touch it.

## Build

- **Tool map.** `Mobile/catalogue/tools.json` maps a tool to its paths: Planner → `Planner/projects/varler-planner/`,
  Inventory → `Inventory/`, Kódváros → `CodeCity/`, VRG Mobile → `Mobile/`, and so on. Generate it once with a
  Node script from `launcher/menu.js` plus a hand-kept list
  for non-page tools. The phone downloads it from `main` (raw contents API), so it updates without an app release.
- `kit-core`: branch → changed files (`GET /repos/{r}/compare/main...{branch}`), files → tools, then the summary
  model, with tests on fixtures.
- `feature-pulse`: `main` (CI ✓ ✗ ●, commit count, last commits), branch cards (name, ahead / behind, last commit
  time + message, PR #), a tools list (file count, the branches touching it), pull to refresh, ETag-cached.
- A tap on a commit or PR opens it on github.com (Custom Tab).

## Tests (cloud)

Compare-payload → tools mapping. A branch touching two tools. A renamed file. A branch behind main only.

**Decided here:** main's week is a comparison from the last commit older than 7 days, because the commits list has no files.
GitHub lists at most 300 files in one, so a bigger week says so and its counts are lower bounds. Coloured dots became branch
names, which read better with so few branches.
