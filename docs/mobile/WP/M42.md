# M42 · Varler Workflow Kit (`workflow`): the PC's quote jobs, sealed to the owner's phone

**Goal.** The office path on the phone: where each Workflow Kit job stands (kérdéssor → anyagkigyűjtés → árazás →
ajánlat → dokumentum), the Költségvetési Tervezet / Árajánlat figures of its variants, and its texts, without the
client data ever being readable outside the PC and the owner's phone. Added 2026-11-19 with the paged home (WP M38,
D-47, page 3); built 2026-11-20 in a cloud session, **BETA**. Decision **D-52**.

## The decision (D-52)

The Founder, 2026-11-20: overall C (a native screen fed by the Planner, the calculators and Készlet), "although A could
be sufficient" (read-only through the relay); "the real problem becomes the client data … Starting with my phone,
could I hold an encrypted copy within my Vault?". The Vault as built (M45, D-53 A) holds no key in VRG Mobile, so a
copy there could not feed this screen. Asked next, the Founder chose **C: sealed to the device via GitHub**: the PC
encrypts each pack to the phone's own device key and pushes only the ciphertext to a private branch.

## How it works

```
PC (H:)                                              GitHub (private)            phone
Full\jobs\<CODE>_*\  ─ tools/workflow-seal.js seal ─► workflow-sealed:           ◄─ ⟳  sealed/<ID>.json, kept as is
  offer.json, *.md, funnel, …   (pack → gzip →         keys/<ID>.json  ◄────────── Kulcs közzététele (public key only)
                                 AES-GCM to the        sealed/<ID>.json            opened in memory with the
                                 phone's P-256 key)                                Keystore-protected device key
```

- **The key** is the Eszközök device key (WP M35, P-256, private half in the Keystore-backed `SecretStore`). The phone
  publishes only its public half as `keys/<ID>.json`; the first publish creates the branch as an orphan (README + key).
- **Trust is on the PC.** `workflow-seal.js` seals only to a phone that is (1) on `Mobile/trust/devices.json` and (2)
  pinned in `Full\_admin\keys\workflow-recipients.json` (outside Git) by `trust <ID> <CODE>`, where CODE is the
  6 characters the phone's screen shows (the Eszközök code over its id and key). A key swapped on the branch is refused
  until trusted again; a phone taken off the list loses its sealed file on the next seal.
- **The seal**: P-256 ECDH with a fresh key per seal, the raw secret as the AES-256-GCM key (WebCrypto's deriveKey, as
  DeviceTrust), a 12-byte IV, `vrg-wk-sealed/1/<ID>` as additional data, gzip inside. Readable without the key: the
  recipient id, the time and the job count.
- **The pack** (`vrg-wk-pack` v1), per job folder `<CODE>_<anything>` in `Full\jobs`: code, folder, title, address
  (decisions.json / answers_r1.json), which steps have a file, `offer.json`'s priced variants (labour, material,
  total, man-hours, days, m²), the job's `.md` texts (≤ 64 KB each, ≤ 768 KB a job; the offer first) and the file
  list (names, sizes). **No PDF content**: the PDFs stay in PC ablakok (◣ → Workflow Kit, M23).
- **The branch is written with git plumbing** (a private index, `commit-tree`, push of that commit), so the PC's
  working tree and branch are never touched; never forced. An unchanged pack is not sealed again (`--force` does).

## As built

- **kit-core `Workflow`** (`WorkflowTest`, 6 tests): `WkKey`, `WkSealed`, the pack model, `seal` / `open`, `ft`
  (1 270 000 Ft), `effort`; a fixture sealed by Node (`Mobile/tests/fixtures/workflow-sealed.json`) is opened on the JVM.

- **`feature-workflow`**: the job list (code · title, stage, each variant's total), a job page (steps ✓, variants with

  whole screen. The opened pack lives only in the screen's state; on disk there is only the sealed file.

## Telefonon ellenőrizni

1. Kezdőlap → page 3 → Varler Workflow Kit: "Teszt" tile; tap → WORKFLOW KIT with "Még nincs csomag ezen a
   telefonon." and, under Ez a telefon, the id (the Eszközök code without dashes) and a 6-character code.
2. A screenshot here is refused; the recents view is blank; Képernyő (M13) on the PC shows black. Back on the home,
   screenshots work again.
3. *Kulcs közzététele* (signed in with write access): the note "Kulcs közzétéve…"; on github.com the branch
   `workflow-sealed` exists with `README.md` and `keys/<ID>.json` (a public key only). A second tap (*Kulcs újra*)
   updates the same file.
4. ⟳ before the PC has sealed: "Még nincs csomag ennek a telefonnak. A PC-n: trust, aztán seal."
5. On the PC (repo root): `node tools/workflow-seal.js status` lists the jobs by code and this phone as "waiting".
   *Parancs másolása* on the phone, then on the PC `node tools/workflow-seal.js trust <ID> <CODE>` with the code from
   the phone: "trusted". A wrong code is refused.
6. `node tools/workflow-seal.js seal`: "sealed" for this phone and "pushed … to workflow-sealed". On github.com
   `sealed/<ID>.json` holds no address, name or sum in clear.
7. ⟳ on the phone: "Letöltve: N munka…"; the list shows each job with its stage and the variants' totals.
8. A job: the five steps with ✓ where the PC has a file; the variants with munkadíj, anyag and eó · nap · m²; the
   address; a text opens and Back returns to the job, Back again to the list.
9. Airplane mode, leave and reopen the screen: the list opens again (the sealed file is on the phone).
10. *PC ablakok ›* opens PC ablakok; with the paired PC, ◣ → Workflow Kit shows the PDFs.
11. *Törlés a telefonról*: the list is gone; ⟳ brings it back.
12. Second seal without changes on the PC: "unchanged since the last seal", nothing pushed.
13. Katalógus → Varler Workflow Kit: the new text; long press on the tile → Leírás opens it.
