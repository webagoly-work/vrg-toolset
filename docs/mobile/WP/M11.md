# M11 · Indítópult (`launch`): START.cmd from the phone

**Goal.** The tools of START.cmd (and VRG-DE.cmd's projects) are listed on the phone. A tap starts one on the PC.
It also shows what is running and the tail of its log. This uses the relay and needs M2 pairing.

## Build

- **Relay**:
  - `launch.list` → the registry read through `launcher/menu.js` from `launcher/vrg-menu.json` (was `T<n>_NAME` / `T<n>_PATH`, the same parser as
    `tools/check-start.js`; share it as a module rather than copying) plus the letter actions it is safe to run
    (A, G, K, …). Keep these as an explicit allow-list in `Mobile/catalogue/launch.json`.
  - `launch.run {id}` → opens the tool page in the portable Chrome / the system browser, or runs the allowed
    action **detached** (`explorer.exe` / `start ""`). Processes started from a tool call die with it (CLAUDE.md /
    memory: launch detached). The id must be in the list: the relay never runs a string from the phone.
  - `launch.status` → which of the list's servers are up (reuses M8's port scan).
- `feature-launch`: the tools as a grid with their START.cmd numbers (the user knows them by heart; keep them),
  a running dot, and a long-press for "Megnyitás a telefonon" (M8) when the tool serves a port.
- Légegér gets a macro step `launch <id>` (`airdeck-core/Macros.kt`) so a macro can open a tool.

## Tests (cloud)

Node: the registry from `launcher/vrg-menu.json` (it must list every tool), an id outside the list being refused, and
command construction never interpolating phone input.

**What was built**

- **Relay** (`Planner/projects/varler-planner/tools/`): `relay-launch.js` (new: the list, the id check, the
  commands, the launcher) and `phone-relay-server.js` (the 6 Nov note at its top). All five messages need a
  trusted phone; an untrusted one gets `{ok:false, trusted:false}`.
  - `launch.list` → `{type:'launch', payload:{ok, entries:[{id, kind, key, name, hint, group, exists, server,
    port, path}], running:[id], mine:[id], proxy:{on, token?}}}`. The registry is read again on every message
    (`menu.reload()`, added to `launcher/menu.js`), so an edit to START shows on the next pull-to-refresh.
    - `tool:<key>`: **every** `start.tools` entry, with its START key as it is (`1`…`9`, `0`, `T`, `D`, `K`, …).
      Its page opens in `Full\tools\chrome\chrome.exe --new-window <page>`, else `rundll32 url.dll,FileProtocolHandler`
      (no `cmd.exe`). Kódváros runs its `before` step (the repo scan) first, as START does. A *served* tool (no
      `path`, a `server` + `page`, the shape the Térkép work is adding) starts its server and opens its URL.
    - `server:<id>`: the registry servers `launch.json` allows (planner, inventory, mindmap, kapu, city, console,
      solomon, divergence), shown with their START → O key (`O1`, `O3`, `OK`, …). Not running → started
      **detached, without a window** (`node <js> <args>`, cwd from the registry), its output appended to
      `%TEMP%\VRG\launch\<id>.log`; then, as START's `OpenServer`, up to 10 s waiting for the port, then its page.
    - `extra:<tool>.<key>`: the tool extras `launch.json` allows: `K.S` (Élő mód) and `K.G` (Gépország; its
      `rundll32 url.dll` line becomes an opened page, so the Chrome fallback applies). `K.F` is left out: its
      first run downloads Electron.
    - `launch.json` → `serves` maps a tool to the server that serves it (1 → planner, 4 → mindmap, 6 → inventory,
      K → city, T → solomon): that is the tool's running dot and its "Megnyitás a telefonon".
  - `launch.run {id}` → `launch.ran {ok, id, how, started, note | reason}`. The id must have the shape
    `(tool|server|extra):<key>` and be a key of the Map built from the registry; nothing else from the phone
    is read, and every command and argument is a registry value.
  - `launch.status` → `{ok, running, mine}` (the M8 netstat scan: `relay-ports.js readListening`, now exported).
  - `launch.log {id}` → the last 40 lines of that entry's server log; `launch.stop {id}` → kills a server only if
    **this relay** started it (by its pid).
