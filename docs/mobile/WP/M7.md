# M7 · Hálózat (`net`): Bluetooth, WiFi relay, hotspot, tethering

**Goal.** One screen for every way the phone links to the PC and the internet, with honest limits.
**Research first.** Android restricts most of this, so the first deliverable is
`docs/mobile/research/M7-network.md`, recording what an ordinary (non-system) app can do on Android 9–15. Ask
the user before building past it.

## Known limits (verify in the research)

- **Hotspot**: an app cannot turn on the regular tethering hotspot (system permission). It *can* open the
  tethering settings directly, read whether tethering is on (the tether-state broadcast / `ConnectivityManager`),
  and start a `LocalOnlyHotspot` (WiFi with no internet: enough for phone ↔ PC relay on a site with no router).
- **Usage notification**: while tethering is on, a foreground service watches `TrafficStats` mobile bytes and
  posts "Hotspot: 1.2 GB ma". There is a user-set warning threshold. Exact per-client numbers are not available.
- **USB tethering / Bluetooth tethering**: not switchable by an app. Detect the state, deep-link to the right
  settings page (vendor differences: test Xiaomi, Sony, Pixel), and explain the one tap needed.
- **BT HID**: Légegér's status (supported, registered, connected host) shown here as well, with a link to it.
- **Phone as the relay** (D-9): if A, a small WebSocket server in the app (Ktor-server-cio or NanoHTTPD),
  speaking the same envelope as `phone-relay-server.js`. The PC apps already look for a relay on a list of
  addresses, so add a way to point them at the phone (Kódváros `36-link.js` and Planner `07a-link.js`).

## Tests (cloud)

The relay-envelope compatibility of the phone relay (if built) against `Mobile/tests/relay-e2e.js`'s fake
clients, run on the JVM. The usage-threshold logic.

## As built (2026-11-07, D-9 = A, stage BETA)

The research is `docs/mobile/research/M7-network.md` (sources cited there). The batch went on past it without a stop,
as the user asked; what the research ruled out is dropped below, not faked.

**Dropped (an ordinary app cannot):** switching the tethering hotspot, USB or Bluetooth tethering on or off (all need
the system-only `TETHER_PRIVILEGED`); per-client usage (no API). Each shows its state and a one-tap settings link
instead, with the one tap left spelled out.

- **The phone relay (D-9 A) is `relay-core`, a new pure-JVM module.** `WsServer` is a small RFC 6455 server written
  here (text frames, masking enforced, fragments joined, 1 MiB cap, ping every 20 s, 60 s idle drop), so the phone
  carries no server framework and the JVM tests run the same code over real sockets. `PhoneRelay` is
  `phone-relay-server.js`'s routing, rule for rule: the `{v, from, seq, t, type, payload, to?}` envelope, `to` by role,
  no echo, no app-to-app, hello replay to a later phone, roster with focus on every hello and close.
- **Who may connect: paired devices only, as on the PC, with the roles turned round.** Every client (not only phones)
  gets `welcome{challenge, pc, relay:'phone'}` and is held: nothing it sends is routed, nothing reaches it, its hello
  goes out only once trusted, and it is closed (4401) after 30 s untrusted. A PC pairs with a code the **phone** shows
  (typed on the PC, so 10 letters from a 31-letter alphabet without look-alikes, ≈ 49 bits, 2 min, single use, burnt
  after 5 wrong tries) and a P-256 key; later it signs `vrg-relay-auth:1:<challenge>:<id>` like the phone does on the
  PC relay. WebCrypto's P1363 signatures and DER are both accepted. The phone's own Keystore key is trusted as `self`,
  so Légegér's link to `127.0.0.1` proves itself through the existing kit `Relay` (one new hook, `localPairing`).
  Paired PCs live in `noBackupFilesDir/phone-relay-paired.json`. The PC relay's PC-side abilities (screenshots, ports,
  launch, board, notify, screen) are answered `{ok:false, unsupported:true}` rather than left silent.
- **feature-net (Hálózat).** One screen: *Telefon relé* (on/off, the addresses best first — own hotspot, USB, WiFi —
  with a copy button, the pairing code with its countdown, live connections, paired PCs with Törlés, "Légegér erre a
  relére"); *Megosztás* (hotspot / USB / Bluetooth tethering on/off from the sticky `TETHER_STATE_CHANGED` broadcast,
  else from interface names, saying which; the settings chain `TETHER_SETTINGS` → `Settings$TetherSettingsActivity` →
  `TetherSettings` → `WIRELESS_SETTINGS`); *Helyi WiFi* (LocalOnlyHotspot: SSID + password, no internet; asks
  `NEARBY_WIFI_DEVICES` on 13+, precise location on 9–12); *Adatforgalom* (the day's mobile data, carried across a
  reboot, plus the hotspot interface's own bytes on Android 12+; thresholds 500 MB … 10 GB; one warning a day);
  *Bluetooth HID* (Légegér's phase and host through the new kit `HidStatus`, with links to Légegér and Bluetooth).
- **NetService**, a `connectedDevice` foreground service (declared with `CHANGE_NETWORK_STATE`, research §5), holds
  the relay and the usage watch, one ongoing notification with Leállítás. Started only from a tap; `START_NOT_STICKY`,
  so a killed relay never comes back on its own.
- **The PC apps.** Kódváros `36-link.js` and the Planner `07a-link.js` carry the same `vrgPhoneRelayAuth` block
  (checked identical by the test). Kódváros: `vrg-codecity.html?relay=<phone>[:<port>][&pair=<code>]` (the port form
  is new). Planner: `varler_planner.html?relay=<phone>[&pair=<code>]` connects at once, or
  `PLANNER_LINK.connectPhone(addr, code)`. Without a code the page asks for it once (`prompt`). The key is kept in
  `localStorage` per phone (in memory when the page cannot store, e.g. `file://` in some browsers: then the code is
  asked again next time). The PC relay never sends `relay:'phone'`, so nothing changes there.
- **kit-core** `Net.kt` (interface names → link, the tether state from the two signals, the relay's address order,
  the settings chain, the hints) and `Usage.kt` (the day counter, reboot carry, the once-a-day threshold).

**Tests:** relay-core 13 (`PhoneRelayTest` 8 replaying `relay-e2e.js`'s traffic: Planner and Kódváros hellos, focus,
phone hello and replay, roster, cmd/keys/gesture to codecity, no app-to-app, screenshot answered unsupported, focus
change, the Planner leaving; plus the gate, codes, forget, P1363 ↔ DER and a Node WebCrypto signature from
`Mobile/tests/fixtures/phone-relay-webcrypto.json`; `WsServerTest` 4 over real sockets with the JDK's WebSocket client;
`JsonNamesTest`). kit-core `NetTest` 7 (the usage-threshold logic among them). `Mobile/tests/relay-phone-link.js` 24
(the block in both apps, run with Node's WebCrypto against PhoneRelay's messages; the Planner's whole `07a-link.js`).

## What I could not verify here

- Nothing ran on a phone: tether detection, the settings links, LocalOnlyHotspot, the usage figures and the service
  with the screen off are all the phone list below.
- Whether `TrafficStats` mobile bytes include tethered traffic is not documented (research §3); the screen calls the
  figure "mobilnet ma", not "hotspot".
- `Mobile/tests/relay-e2e.js` (real Kódváros page in Playwright) did not run: Playwright is not installed on this PC.
  The phone relay's routing is replayed on the JVM instead, and `36-link.js`'s new block is tested in Node.
- `CodeCity/dist/vrg-codecity.html` was not rebuilt in this commit (another session has uncommitted Kódváros work in
  `CodeCity/`); the phone-relay pairing reaches the city page at its next build.
- `file://` pages and `localStorage`: where the browser refuses storage, the pairing lasts one page load.

## Telefonon ellenőrizni

A kutatás mátrixa (`docs/mobile/research/M7-network.md`, minden sor a Redmi Note 13 Pro 5G-n, és ha kéznél van,
Pixelen és Sonyn):

- [ ] Hálózat → Megosztás → „Beállítások ›”: a hotspot / megosztás oldala nyílik meg (Xiaomi: Kapcsolat és megosztás).
- [ ] WiFi hotspot be / ki: a sor 1–2 mp-en belül követi; alul a „Forrás” sor (rendszer jelzése vagy becslés).
- [ ] USB-megosztás be / ki (kábellel a PC-n): a sor követi.
- [ ] Bluetooth-megosztás be / ki: a sor követi.
- [ ] Helyi WiFi → Indítás: engedélykérés, majd hálózatnév + jelszó; a PC csatlakozik rá, internet nincs.
- [ ] Adatforgalom: a „Mobilnet ma” nő, amíg a PC a hotspoton letölt; Android 12+ alatt a „hotspot” szám is.
- [ ] Figyelés bekapcsolva, alacsony határ (500 MB): egy értesítés jön, aznap nem többször; az állandó értesítésben
      „Hotspot: … · mobilnet ma: …”, és a Leállítás mindent leállít.
- [ ] Bluetooth HID: a sor ugyanazt mutatja, mint Légegér (Kész / Csatlakozva + a PC neve); „Légegér ›” odavisz.
- [ ] Telefon relé → Relé fut: értesítés „Telefon relé fut”; a címek között a hotspot / WiFi cím.
- [ ] A PC-n Kódváros `…/vrg-codecity.html?relay=<cím>` (a következő Kódváros build után) és Planner
      `…/varler_planner.html?relay=<cím>`: kódot kér, „Új párosító kód” a telefonon, beírva összekapcsolódik;
      újratöltés után már nem kér kódot.
- [ ] „Légegér erre a relére”, majd Légegér: a Planner és Kódváros vezérelhető a telefon reléjén át.
- [ ] Párosított PC törlése a telefonon: a PC kapcsolata azonnal megszakad, újra kódot kér.
- [ ] Ismeretlen eszköz (kód nélkül) 30 mp után kidobva; rossz kód ötször → a kód elég, újat kell kérni.
- [ ] A relé 10 percig fut kikapcsolt képernyővel (a Xiaomi akkumulátor-kímélője nem állítja le).
