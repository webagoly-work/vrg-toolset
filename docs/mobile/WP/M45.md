# M45 · Vault (`vault`): the Proton Vault's own web app inside VRG Mobile

**Goal.** The personal encrypted vault (`webagoly-work/data-vault`, Proton Vault) reachable from VRG Mobile. Added
2026-11-19 with the paged home (WP M38, D-47, page 4); built 2026-11-20 in a cloud session, **BETA**. Decisions
D-48 (what it is) and D-49 (its approval), both asked and answered by the Founder.

## What it is (D-48 = A, D-49 = A)

- **The Vault's own web app in a confined WebView**, not a native reader: the Vault keeps its own crypto, so VRG
  Mobile holds no vault key and decrypts nothing. A native reader (D-48 B) is a later step, kept as a reminder.
- **A separate approval.** The page keeps its own device identity (its P-256 key in its own storage, PV-D11) and
  asks the Vault's own QR approval (PV-D12). Being approved in Eszközök (M35) does not open the vault, and the
  Keystore-backed VRG device key never reaches the page.

## As built

- **kit-core `VaultWeb`** (pure JVM, `VaultWebTest`): the address (`DEFAULT_URL` =
  `https://webagoly-work.github.io/data-vault/`, https only, no user info, settable), the origin, in-place navigation
  only inside the Vault's path (github.io serves every Pages site of the account on one origin, so `/vrg-toolset/`
  opens in the browser), requests only to the Vault's origin and `api.github.com` / `raw.githubusercontent.com` /
  `github.com`, a pasted link found in a whole message, and `forLog` (the origin only, never a path, query or
  `#grant=` fragment).
- **`feature-vault`**: the page full size under a small top row (‹ · VAULT · ⟳ · ⚙). The WebView: JavaScript and DOM
  storage on, file / content access off, no mixed content, no pop-up windows, no third-party cookies, no geolocation;
  every request off the allowed list gets an empty 403; a link out opens in the phone's browser; downloads are
  refused with a note (nothing decrypted reaches shared storage); the camera only for the Vault's own origin and only
  when the app already holds the permission (the Vault's own QR scanner); `<input type=file>` opens the document
  picker (reading only). **FLAG_SECURE** while the Vault is on screen: no screenshots, recents thumbnail or screen
  cast (Képernyő, M13, shows black there). The page's console is never logged.
- **⚙**: the Vault's address (Mentés / Alapérték; another address is another device for the Vault), *Vault-link
  megnyitása* (a Vault link from a message opens here, not in the browser, so it reaches this app's device key),
  *A Vault adatai a telefonról* → *Törlés…* → *Igen, törlés* (localStorage, IndexedDB, caches and the service worker
  of the page, then WebStorage; this phone becomes a new, unapproved device in the Vault).
- `vrg://vault?open=<link inside the Vault>` loads that link in the page; any other link is refused.
- Catalogue `vault` → **BETA**, needs only internet (the GitHub sign-in is the Vault's own); its Katalógus page is
  rewritten (`CatalogGuide`).

## What I could not verify here

- **The data-vault repo was not readable in this session** (attaching it was refused), so the default address, the
  hosts the page needs and whether its grant comes back as `…#grant=` are taken from M35's description of the Vault,
  not from its code. If the page does not load or a request fails: ⚙ → the address, and `VaultWeb.ALLOWED_HOSTS`.
- The APK compile is Actions' (`VRG Mobile (Android)`); the cloud sandbox runs only the JVM tests.
- WebView `evaluateJavascript` does not await the wipe's promise; the app waits 800 ms before reloading.

## Telefonon ellenőrizni

1. Kezdőlap → page 4 → Vault: "Teszt" tile; tap → the Vault's own page loads under ‹ VAULT ⟳ ⚙. (If it does not:
   ⚙ → the address of the Vault's web app → Mentés.)
2. First open: the Vault treats this phone as a new device and offers its own access request. Approve it on the owner's
   phone the Vault's way; the Vault opens on this phone. Eszközök (M35) is unchanged.
3. Leave and come back, also after closing the app: still approved (the device key stayed).
4. A screenshot on the Vault screen is refused; the recents view shows it blank; Képernyő on the PC shows black. Back on
   the home, screenshots work again.
5. A link in the Vault to another site opens in the phone's browser; the Vault stays on its page.
6. A download from the Vault (if it offers one): the note "A Vault letöltéseit a VRG Mobile nem menti…", nothing in
   Letöltések.
7. ⚙ → *Vault-link megnyitása*: paste a whole message with a Vault link → it opens in the page; a link of another site
   → "Ez nem a Vault címén lévő link."
8. If the Vault has its own QR scanner: it gets the camera (after the app's camera permission was given once in QR beolvasás).
9. ⚙ → *Törlés…* → *Igen, törlés*: the note; the Vault now sees a new, unapproved device (step 2 again).
10. Back: steps back inside the Vault, then to the home; Back with ⚙ open closes ⚙ first.
11. Katalógus → Vault: the new text; long press on the tile → Leírás opens it.
