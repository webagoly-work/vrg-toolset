# M25 · Fotópont (`photo`): photos of every room, taken from a point on the sketch, with their direction

**Goal.** The second version of the Vázlat (M24), in the user's words of 2026-11-17: *"a Photo-Point: a user marks a
spot in the middle of the room, opens this point which opens as a camera application, takes a photo of the room
from the point placed on the sketch; the Photo-Point waits for a directional swipe from the point toward a direction,
to save the orientation with the photo (4 pictures from every room map out everything visually)."*
**PLANNED** — not built. The catalogue entry (`Catalogue.PHOTO`, PLANNED, needs the camera), the plugin
(`Plugins.PHOTO`, `built = false`), the tool (`Tools.PHOTO`) and the data slot are already in M24.

## What is already in place (M24)

- The sketch file keeps `photos: [{id: 'F…', at, room, shots: [{deg, file, taken}]}]` (`Model.kt` `PhotoPoint` /
  `Shot`; `deg` 0 = up on the sketch, clockwise). It round-trips through a phone without M25, so no photo point is
  lost by an older app.
- `Ops.hit` finds photo points (`Hit.Kind.PHOTO`), `Ops.delete` removes them, and the hold wheel has a Fotópont wheel
  slot. The ⚙ sheet lists the plugin as *M25, tervben*.

## Build (proposed)

1. **The point.** With the plugin on, the ◉ Fotópont tool: a tap in a room places the point (snapping to the room's
   centroid within a fingertip, as the request says "the middle of the room"). One per room by default, more allowed.
2. **The camera.** Tapping the point opens a full-screen CameraX preview (feature-pair already uses CameraX for the QR
   scanner, so the dependency is in the app). The shutter takes the photo into `files/sketch/<sketch>/F<n>-<k>.jpg`.
3. **The direction swipe.** After the shot the sketch comes back with the point under the finger area and a ghost
   arrow: a swipe from the point toward a direction saves that direction as the shot's `deg` (snapped as D-24 decides).
   The four directions already taken show as wedges on the point; the next missing one pulses, so four photos per room
   are one tap and one swipe each.
4. **Looking at them.** Tapping a wedge shows the photo; the hold wheel on a photo point: Fotó újra, Irány javítása,
   Memó, Címke, Törlés.
5. **Export and the Planner.** The photos travel with the package (D-25), and the Planner shows each photo point as a
   camera mark with its view cones on the floor; clicking a cone opens the photo. (Planner side: a small module next to
   `08ca-sketch-import.js`; the Planner has photo-in-plan prior art in `07b-phone-camera.js`.)

## Open decisions (ask when M25 starts, recommendation first)

- **D-24 · The direction.** **A** snap to the four sides of the room as drawn (N, E, S, W of the sketch: what "4
  pictures from every room" needs, and the Planner's view cones stay tidy); B eight directions; C the exact swipe angle.
- **D-25 · How the photos reach the PC.** **A** each photo goes onto the Átadás board as its own file, tagged for the
  Planner (M12's photo tagging), and the package names them; B one `.zip` with the package and the photos; C the photos
  inside the JSON as base64 (simplest, but a four-room flat is 15–40 MB of JSON).
- **D-26 · The compass.** **A** none: the swipe is the direction, relative to the sketch (the sketch is not north-up
  anyway); B record the phone's compass heading as well, for a later "true north" option; C use the compass instead
  of the swipe.

## Telefonon ellenőrizni (when built)

Fotópont plugin on; a point in each room; four photos per room with a swipe each; the wedges; a photo opened from its
wedge; the app closed between two shots; the package on the PC with the photos; the Planner's view cones.
