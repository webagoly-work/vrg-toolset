# M48 · Helyszín ↔ Térkép: the outline drawn on the phone's own map, the sketch placed on the building

**Goal.** The Founder: a job's address *"can be used to plug in an embedded window from the VRG Map — not just to display
it, but to help the system later to gain geolocation related information, including comparing the sketches to the
outer dimensions **and position** of the building on the address for cross referencing."* M30 did the sizes through a
paired PC only; this closes the rest. Built 2026-11-20 in the fork session **F1** (`docs/sketcher/FORKS.md`), branch
`sketcher/f1-helyszin`, **BETA**. Decisions D-62 … D-66 (`../DECISIONS.md`).

## Build

- **Data** (`sketch-core` `Model.kt`, `SitePlace.kt`; the survey stays **v2**, the keys are optional, an old file opens
  unchanged — tested): `site.outline` = `[[lat, lon], …]` (3–200 corners), `site.place` = `{lat, lon, rot, auto, at}`:
  the plan's box centre on the map, turned `rot` degrees clockwise; `auto` while it is still the automatic fit.
  `site.footprint` stays (now measured again from the outline whenever it changes; `src` `osm` / `rajz` / `muhold`).
- **The maths, twice, one fixture.** `Map/lib/site-math.js` (the map page and the Desktop) and `SitePlace.kt` (the
  phone) implement the same oriented box, auto-fit and report; `Sketcher/tools/make-site-fixture.js` writes
  `Sketcher/test/fixtures/site.json` (7 synthetic cases: turned house, user-turned, L-shapes, a flat in a block, a plan
  too big, a plan drawn rotated, no plan) from the JS, and `SitePlaceTest` replays it (D-65 has the rules).
- **The map page** (`Map/lib/site-layer.js`, loaded by `Map/vrg-terkep.html` as plain scripts): opens only when a
  host hands it a survey — the phone through `window.vrgSite.open`, the Desktop Sketcher through `postMessage` (the
  answer goes back to that window only). 3D buildings are hidden and the map lies flat while it is open.
- **Phone ↔ map ↔ Sketcher** (D-62): Helyszín saves the survey and opens `vrg://map?site=<id>`; the page reads
  `/__phone/site.json?id=<id>` (the place, the outline, the placement and the solved rooms in metres; **no address**);
  ✓ Kész → `vrg-map:site?d=<answer>` → the map writes `files/sketch/handoff/<id>.site.json` and opens
  `vrg://sketch?open=<id>&front=helyszin`; the Sketcher applies the answer when it opens the survey (even after the app
  was killed in between) and deletes the file. ✕, ‹ and Back return without changes.
- **On the phone, without the map:** the Helyszín front shows the same report lines, **⤢ Illesztés** and
  **✕ Elhelyezés**; the OSM outline is stored as the polygon, so it can be placed against at once.
- **Desktop** (`Sketcher/src/app.js`, built to `Sketcher/dist/vrg-sketcher.html`): *A vázlat az épületen* card: the
  outline and the placed rooms drawn north-up, walls that stick out in red, the report, ⤢ / ✕, and **🗺 Szerkesztés a
  térképen**, which hands the survey to the embedded VRG Térkép (`localhost:8802`) and applies its ✓ Kész.
- **Found on the way, fixed (D-66):** `Map/vrg-terkep.html` on `main` imports `/lib/weather-layer.js` (the W layer),
  which the phone neither fetched nor served: a failed module import stops the whole page, so VRG Térkép on the phone
  was broken since the W layer landed. The phone now fetches and serves every lib file the page loads (`MapPhone.PAGE_FILES`,
  `MapPhoneTest` checks it from the page itself), and the page loads the weather layer with a dynamic import, so an older
  app keeps working.

## Privacy

Offline-first; nothing goes out unasked. The site page gets no address. The satellite tiles go out only after 🛰 (the
coordinates of the tiles in view, to Esri), the WebView does not cache them and the tile cache never sees them. OSM is
asked as in M30 (the address on 🔎, the coordinates on ▱). No client's place in Git: the fixture is synthetic.

## Telefonon ellenőrizni

1. Egy felmérésben rajzolj két szobát, adj méreteket (Rendezés: legyen megoldott terv). Helyszín → ⌖ Itt vagyok (GPS).
2. **🗺 Körvonal és vázlat a térképen** → a VRG Térkép nyílik (PC nélkül is: a fejlécben Internet), felülnézetben, a
   helyedre; alul a lila **Helyszín** panel.
3. **🛰 Műhold** → a műholdkép megjelenik, alatta az Esri felirat. Kapcsold ki és be: csak koppintásra jön.
4. **▱ Körvonal**: koppints a ház sarkaira sorban → lila körvonal; húzz el egy sarkot → követi; a fehér pontot húzva új
   sarok; egy sarokra koppintva **✕ Sarok** törli.
5. **◫ Vázlat** → a vázlat rákerül, a ház falaihoz forgatva; alul „A vázlat a körvonalon belül van…” vagy mi lóg ki.
   Húzd el az ujjaddal, forgasd **⟳ 15°**-kal → piros falak, „… fala kilóg”; **⤢ Illesztés** → vissza.
6. **⇣ Hely átvétele**, majd **✓ Kész** → visszajön a Sketcher **Helyszín** nézete: a körvonal mérete („műholdról
   rajzolt”), a vázlat az épületen sorai, a koordináta „VRG Térkép”.
7. Zárd be az appot, nyisd újra, nyisd meg a felmérést: minden megmaradt. A térképet újra megnyitva a körvonal és a
   vázlat ott van, ahol hagytad.
8. A térképen **✕** vagy a vissza gomb → a Helyszínre jön vissza, változás nélkül.
9. Helyszín → **▱ Épület körvonala** (OSM) egy családi háznál → a körvonal azonnal elhelyezhető: **⤢ Illesztés** a
   telefonon, térkép nélkül; **✕ Elhelyezés** törli.
10. A **második telefonon** ugyanez egy másik felméréssel; utána a VRG Térkép kezdőlapról nyitva a sima térkép jön (nem a
    helyszín panel), a lila pöttyök ott vannak.
11. Asztal: a csomagot nyisd meg a VRG Sketcher Asztal oldalán (START S) → Helyszín → *A vázlat az épületen* ugyanazt
    mutatja; a START H szerverrel **🗺 Szerkesztés a térképen** → a lenti térképen módosíts, ✓ Kész → átveszi; Mentés.
12. A VRG Térkép a telefonon a Helyszín nélkül is nyílik (a W időjárás réteg miatt eddig nem nyílt — D-66).
