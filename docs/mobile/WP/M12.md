# M12 · Átadás (`drop`): the file board between the phone and the PC

**Goal.** A shared board that both sides can drop files on and take copies from, plus the direct routes to the right
place on the PC:
- files in either direction (a supplier PDF received on the phone, a drawing from the PC for the site);
- photos (site pictures for the Planner, labels for the Inventory);
- the clipboard (both ways);
- Légegér's screenshots, which already come PC → phone.

This uses the relay and needs M2 pairing. It works while the relay runs and the phone can reach the PC (same WiFi,
hotspot or USB tethering). Traffic is plain HTTP, so on a shared network it can be read: use a hotspot for client
files on a site.

## The board

One folder, `H:\VRG\Full\inbox\board\`, outside the repo: client PDFs must never land in the repo (CLAUDE.md: `*.pdf`).
The relay finds it next to the repo (`path.join(path.dirname(REPO), 'inbox', 'board')`, the rule CLAUDE.md gives for the
toolchain), and `RELAY_BOARD_DIR` overrides it for tests, as `RELAY_PAIRED_FILE` does. Files go in `<YYYY-MM-DD>\` under
it, and `board.json` lists them: `{id, name, bytes, sha256, from: 'pc'|'phone', at, target}`.

- Taking a file gives a copy; it stays on the board for the other side and for a second device.
- Removing an entry moves the file to `board\_removed\`. Nothing is deleted automatically, and the user empties that
  folder. A removed id stops being served at once.
- An interrupted transfer never appears: the upload goes to a `.part` file, and only a complete one with the right
  size and SHA-256 is renamed and listed.

## Who may use it

| Who | How | Rule |
|---|---|---|
| The PC's browser | `http://localhost:47291/board` | The `/pair` rule (`isLocal` + `isLocalHost`), **plus** every POST must carry this relay's own `Origin`. The `/pair` rule alone does not stop a website open in the same browser from posting to localhost. |
| VRG Mobile | HTTP on the PC's LAN address, from the paired relay link | A trusted WebSocket asks for a ticket (`board.ticket`): random 128-bit, one transfer, 60 s, sent in a header, never in the URL. |
| A phone browser, or a phone without the app | Not in M12 | An untrusted client gets nothing. Later, if wanted: a one-time QR on the PC's `/board` page. |

## Build

- **Relay** (the board in its own `tools/relay-board.js`, tested alone like `relay-pair.js`):
  - `GET /board`: the PC's page, in the Mélyvíz look: drag in, list, download, remove.
  - `GET /board/list.json`, `GET /board/file/<id>` (download), `POST /board/upload?name=&sha256=&target=` (streamed to
    disk, 50 MB limit), `POST /board/remove?id=`.
  - The stored name is sanitised and never decides the path outside the folder. Files are always served with
    `Content-Disposition: attachment`, `X-Content-Type-Options: nosniff` and `Cache-Control: no-store`, so an uploaded
    HTML file cannot run on the relay's address.
  - `{type:'board', payload:{id, name, bytes, from, target}}` tells both sides, so lists refresh without a reload.
  - `target` routes a file that landed on the board; it stays listed in every case:
    - `planner`: the existing `07b-phone-camera.js` photo path, into the open job;
    - `inventory`: the import queue;
    - `inbox`: nothing more, it just stays on the board.
  - `clip.set` / `clip.get` (text only) between the phone and the PC clipboard (PowerShell `Set-Clipboard` / `Get-Clipboard`).
- `feature-drop`: the board's list with download and remove, a share target ("Megosztás → VRG Mobile → PC-re"), a picker,
  a target choice and progress. A camera button takes a photo straight to the Planner. Downloads go to the phone's
  Letöltések through MediaStore.
- Reuse Légegér's `ShotStore` for what a board download needs (move it to `kit` if both use it).
- `launcher/vrg-menu.json`: the relay's entry gets the board's address; run `node tools/check-start.js`.

## Tests (cloud)

Node, `Mobile/tests/relay-board.js`, with its own port and a temporary folder:
- the size limit; a broken or wrong-checksum upload leaves no entry and no `.part`;
- the path stays in the board folder (no `..`, no absolute or reserved names, the name sanitised);
- the same name twice gives two entries, neither overwritten;
- an untrusted phone, a foreign `Host`, a foreign or missing `Origin` on a POST: all refused;
- a ticket works once, and not after 60 s;
- a removed id gives 404, and the file is in `_removed`;
- the download headers; the clipboard is text only.

## Telefonon ellenőrizni

- [ ] Share a photo from the gallery → it appears on the board on the PC, and in `inbox\board\<today>`.
- [ ] With the Planner open, a camera photo lands in the job, and it is on the board too.

- [ ] Turn the phone's WiFi off mid-upload → no half file on the board.
