# M24 · Csipogó (`pager`): the Site Pager on the crew's phones

**Goal.** The Site Pager idea, rebuilt as a VRG Mobile feature: phones that page each other over Bluetooth with no
internet, no PC and no pairing dialog. It keeps enough of the original design that the buttons, the messages and
the receipts are the pager's, and it adds what a phone does better. Asked for by the Founder on 2026-11-18. Stage **BETA**.

## Where it comes from (research, 2026-11-18)

The Site Pager was a hardware project next to BRIDGE ("adjacent, reference only", `BRIDGE/BRIDGE-PRIMER-001`). It
was a pair of belt pagers, each an ESP32-S3-Zero with an nRF905 433 MHz radio and an OLED, carried by two
electricians, plus a module ecosystem. Three sources in this repo and on claude.ai hold it:

- **`Archive/files/site-pager-builder.html`**: the *Site Pager Builder*, a Mark II bench simulator for the B2 belt
  pager and the A2 modular unit. It holds the message table, the packet types, the button legend per mode, the
  GUARD state machine, the module catalogue, the radio model (log-distance path loss, clutter 2.2 / 2.7 / 3.2)
  and the third-unit study.
- **The "Site Pager Pair — Mark Plan" doc** (Claude Docs, linked from `Archive/index.json`): the Mark ladder
  (Mark I v1.4 → Mark II "Field Kit" → III / IV), the talent tree (LINK, CONTROL, TRACE, SENSE, HUD, POWER), the
  key fob / HUB / GUARD modes, the third unit (T1 Site Base, T2 Stair Node, T3 Crew Console, T4 Wear Pod), 36
  modules and the enclosure work.
- **`BRIDGE/05_standards/BRIDGE-STD-005`, `-008`** and `BRIDGE/_build/BRIDGE-A-002_decisions.md`: the nRF905 band
  note and the open "unify the indicator language" item (pager, notification light, follow pendant, HID deck).

The firmware repo itself (`site-pager`, a git bundle and a zip) is not in this repository; the spec it cites
(`CLAUDE.md §19–22` there) was read through the builder and the Mark Plan instead.

| 14 messages (COME HERE … LOW BATTERY), codes 1–14 | the same codes, Hungarian labels (`pager-core` `Messages`) |
| every message acknowledged (**GOTIT**), retried; RGB green / red | GOTIT from each receiving phone; green = delivered, red = NO REPLY after 8 s, amber = sending |
| **LINK** short = link test (PING), Range Map zones | LINK tap = link test with RSSI and distance; LINK long = roll call |
| 8-byte payload `[type, arg, src, dst, seq, ttl, crew, 0x5A]`, types 1–14 | exactly that frame inside the BLE beacon (type 0 = idle presence) |
| K2 **Crew IDs**: unit 1–8, ALL-call, per-crew address | crew code → crew id byte + MAC key; units 1–30; dst 0 = everyone |
| **GUARD**: loop closed to arm, exit delay 5/15/30 s, 5 s entry, ALARM every 2 s until acked then 30 s, partner-only disarm, ARM / DISARM PARTNER | **Őrzés**: the accelerometer is the loop (lying still to arm, moved or tilted = trigger); the same delays, pages and remote arm / disarm (`HUBCMD` target 4) |

| POWER OFF "also shows WORKING ON C4 — DO NOT SWITCH … a sign, not a lockout" | KAPCSOLD LE / FEL say on screen that a message is not a lockout (LOTO rules apply) and to wait for LÁTTA; in the full list they need a long press |

## What the phone adds (chosen, as the Founder asked)

1. **Közelség (proximity).** Every beacon is also a distance probe: median + EMA filtered RSSI, the builder's own
   path-loss model run backwards, zones (közel / közepes / messze / határon / nincs jel), a trend arrow
   (közeledik / távolodik), and "heard only through a relay". A **1 m calibration** per crew member corrects for
   phone models. Rounded on purpose ("~4 m", "~25 m", "40+ m"): it is a hint, not a tape measure.
2. **Keresés (finder).** Tap a person: a big distance readout and a sonar tick that speeds up as you get closer,
   plus a 2 s HÍVÁS so their phone rings while you look for it. Answers "which room is he in?".
3. **Csevegés (chat).** Free text over the links, to everyone or one person; acknowledged per receiver; carried
   across the link mesh (3 hops); **store and forward**: a message waits up to an hour for someone to come in range.
4. **Adóvevő (walkie-talkie).** Half-duplex push-to-talk, 8 kHz IMA ADPCM (32 kbit/s), roger beep, FOGLALT when
   someone else talks.
5. **Vészjelzés (SOS).** A long press sends ALARM reason 8 to everyone.
6. **Automatic GYENGE AKKU.** A phone that drops under 15 % sends message 14 itself, once.
7. **Answer from the lock screen.** Every page is a notification with LÁTTAM on it; the ongoing notification has
   LÁTTAM and Kikapcsolás. Alarms ring on the alarm stream, so a silenced phone still sounds for RIASZTÁS.
8. **Crew invite link.** `vrg://pager?crew=CODE`, shared from Beállítás; opening it asks before switching crews.
9. **Unit clash warning.** Two phones with the same unit number are spotted and named.

Left out deliberately: the HUB mode's LIGHT / HEAVY ports and ESP-NOW modules (a phone has no ports; the ports
belong to a future hardware unit that could join the same frame), the 433 MHz key fob, LoRa.

## How it works

`pager-core` (pure JVM, the rules) + `feature-pager` (the Android shell), as every WP since M7.

### The beacon (connectionless, every phone, ~10 per second)

One legacy BLE advertisement, connectable and scannable. Manufacturer data under company id `0xFFFF` (the SIG's
test id; a closed crew tool, never a product), 23 bytes:

| Bytes | Field |
|---|---|
| 0–1 | `'V' 'P'` |
| 2 | version (4 bits) · flags: link open, talking, guard armed, alarm |
| 3 | txUnit: the phone sending this beacon |
| 4–11 | the pager frame `[type, arg, src, dst, seq, ttl, crew, 0x5A]` |
| 12 | battery % |
| 13 | tx@1m (signed dBm, for the distance) |
| 14–15 | L2CAP PSM (0 = none) |
| 16–17 | fast-path GOTIT: `(ackSrc, ackSeq)` |
| 18 | epoch minute mod 256 (replay window ± 2 min) |
| 19–22 | HMAC-SHA256(crew key, bytes 0–18), first 4 bytes |

The scan response carries `'V' 'N' unit name` (20 bytes UTF-8). Pending events and pending acks take turns in the
beacon (400 ms each) until acknowledged or 8 s pass; the advertising set's data is swapped in place
(`AdvertisingSet.setAdvertisingData`), never stop / start. The raw bytes are parsed by hand
(`AdParser`): Android's own map keeps only one entry per company id. A relayed event that reaches its target
gets its GOTIT back as an event too (the fast ack slot would not reach the sender through the relay).

### The link (chat and voice)

Android 10+'s **LE L2CAP connection-oriented channel** (`listenUsingInsecureL2capChannel`): no bonding, so no
pairing dialog. The PSM rides in the beacon; the lower unit number dials. Framing `[u16 len][u8 kind][body]`;
the kinds are HELLO, AUTH, FRAME, CHAT, CHAT_ACK, VOICE, VOICE_END. Both sides prove the crew first (a nonce
each, HMAC of the other's nonce); a socket that does not within 5 s is closed. Pager frames also go over the link
when one is open (faster, and GOTIT comes straight back).

### What it is and is not (security)

- The crew code is a shared secret: the MAC keeps strangers and other crews from sending into a crew, and the minute
  keeps a sniffed beacon from being played back later. A short, guessable code (VRG) is guessable: choose a longer one.
- Nothing is encrypted. Anyone with a BLE sniffer near the site can read which message was sent and hear the
  walkie-talkie. Do not put anything secret in the chat.
- The beacons show that a phone running Csipogó is near (no name in the beacon, the name is in the scan response).

## Tests (cloud)

`./gradlew :pager-core:test` (30 tests, all green 2026-11-18): the message set and key map against the pager's,
the frame, beacon round trip and size, MAC refusal for other crews and forgeries, replay refusal, the raw AD
parser, UTF-8 name cut, the RSSI filter and distance, calibration, ADPCM SNR > 15 dB, the floor, the link codec and
handshake, the guard sequence, man-down (stillness, impact, cancel by movement), and a **simulated crew on a
simulated air**: delivered → seen, no reply, an ALL-call counted per receiver, CALL held and released, a message
carried across floors by the stairwell phone with its GOTIT coming back, a stranger crew counted not shown, a unit
clash, roll call and ping, a guard alarm reaching the crew and a remote disarm, a man-down alarm and its all-clear,
chat over the links with store and forward, chat across a two-hop link mesh, nearest-first proximity and loss.

## What could not be verified here

The Android module (`feature-pager`) was written in a cloud session, where the Android SDK cannot be fetched: its
first compile is the GitHub Actions run. Nothing of it has run on a phone: BLE advertising-set updates, the
scan duty, L2CAP CoC between two phone brands, the audio path, the alarm stream on silent and the battery cost of a
day with the service on (a partial wake lock is held while it runs) are all for the phone check.

## Telefonon ellenőrizni (two phones at least, Android 10+; a third for the relay)

1. Csipogó → Bekapcsolás on both: the permissions are asked, the ongoing notification shows; Közelség lists the
   other phone within a few seconds with a sensible distance.
2. Beállítás: set different names and unit numbers, the same crew code; the names update on the other phone.
3. Panel: K1 short → the other phone vibrates once and shows GYERE IDE; the lamp goes green; LÁTTAM there → the
   lamp goes blue. K2 long (KAPCSOLD FEL) shows the not-a-lockout note.
4. HÍVÁS held for 5 s: the other phone rings for those 5 s and stops within ~2 s of release.
5. Turn one phone's Bluetooth off, send: NINCS VÁLASZ (red) after 8 s.
6. LINK tap: LINK OK with dBm and distance; LINK long: roll call lists the other phone with its battery.
7. Screen off on the receiver, phone in a pocket: a page still arrives (within ~2 s), LÁTTAM works from the
   notification.
8. Csevegés: a message arrives; with the receiver away, send, come back in range: it arrives then.
9. Adóvevő: hold and talk; the other phone plays it; both pressing at once shows FOGLALT on the second. Volume down
   works as PTT while Csipogó is on screen.
10. Keresés: walk away and back: the tick slows and speeds up, the arrow turns. 1 m calibration succeeds.
11. Őrzés: arm on a table, wait the exit delay, pick it up: 5 s later it rings and the other phone gets RIASZTÁS
    (mozgás); Kikapcsol from the other phone stops it. Partner-only disarm refuses the local disarm.
12. Mozdulatlanság at 60 s: leave the phone still → pre-alarm, LÁTTAM cancels; wait it out → the other phone gets
    the alarm; LÁTTAM on the first clears it on the second.
13. Three phones: A and C out of each other's range, B between them with Átjátszó on: A → C arrives marked
    "átjátszva", and A's status turns green.
14. Silent mode on the receiver: RIASZTÁS still sounds.
15. A day's battery cost with the service on, screen mostly off (note it here).
