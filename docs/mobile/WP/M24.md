# M24 · Széf (`vault`): an encrypted vault on the phone

**Goal.** The user asked on 2026-11-17 for a Vault in VRG Mobile: files, folders, documents and ID info that the
user wants kept encrypted on the phone (client data first), locked by a code or by biometrics. Built 2026-11-17,
**BETA**. Decision: D-19 in `../DECISIONS.md` (defaults taken in the session, the user revisits them).

## What it holds

- **Mappák** (folders, nested), **Dokumentumok** (a title and free text), **Adatlapok** (records with fields) and
  **Fájlok** (any file picked with the system picker, or a 📷 photo taken straight into the Széf).
- Record templates, in the "+ Új" order: **Ügyfél** (név, cím, telefon, e-mail, adószám, POD, mérőóra gyári szám,
  kapu- / riasztókód, megjegyzés), **Személyi igazolvány**, **Lakcímkártya**, **Jogosítvány**, **Útlevél**,
  **TAJ és adóazonosító**, **Szakmai jogosultság**, **Bankkártya**, **Belépés**, **WiFi**, **Egyéni adatlap**
  (own fields). A field marked 🔒 shows •••• until 👁, is copied with ⧉ (cleared from the clipboard after 30 s,
  flagged sensitive for Android 13+), and is never searched.
- Any item or folder can be marked **„Megnyitáskor újra azonosítás”**: inside the open Széf it asks for the PIN /
  fingerprint once more (per lock), for everything below a guarded folder too.

## How it is protected

| Layer | What it is |
|---|---|
| Content | One random 256-bit vault key (VK). The index and every file are AES-256-GCM boxes, a fresh nonce each, the item id bound in as associated data (a box cannot be swapped for another). Nothing is written in the clear. |
| PIN / passphrase | 6–12 digits (no runs, no repeats, no common ones) or a passphrase of 8+. PBKDF2-HMAC-SHA256, 310 000 rounds (stored per vault), seals VK. |
| Device | That box is sealed again with a non-exportable Android Keystore key (`vrg-vault-device`). The vault files copied off the phone cannot be brute-forced on a PC; a factory reset makes them unreadable (only a backup brings them back). |
| Biometrics | Optional. VK sealed by a Keystore key that a strong fingerprint / face check releases once per use (`vrg-vault-bio`, invalidated by a newly enrolled fingerprint; the PIN still works). The framework `BiometricPrompt`, no new library. |
| Wrong tries | After the 5th wrong try in a row: 30 s, then 1 min, 5 min, 15 min, 1 h. Optional "10 hibás próba után törlés": the 10th wipes the vault and its keys. |
| Locking | Screen off → locked. App in the background longer than Azonnal / 30 mp / 1 perc (default) / 5 perc → locked. 🔒 any time. A lock forgets VK, empties `cache/vault-out` and the clipboard copy. |
| The screen | `FLAG_SECURE` while the Széf is shown: no screenshots, no recording, a blank card in Recents. |
| Backups | `allowBackup="false"` (the app's), and the vault lives in `noBackupFilesDir/vault`. |

**Getting files out, on purpose only:** ↗ Megnyitás (a decrypted copy in `cache/vault-out` handed to another app,
deleted at the next lock), ⤓ Mentés a telefonra (a plain copy where the user chooses), and the **backup**.

**The backup** (`vrg-szef-YYYY-MM-DD.vrgvault`): the whole Széf sealed with its own password (8+ characters,
PBKDF2), record by record (index, each file, an end mark), so a cut or edited file is refused. Restoring merges: an
item already present is skipped, the rest goes into the folder open in the list. This is the only way to a new phone.

## Build

- `kit-core/Vault.kt` — everything that decides what is safe, pure Kotlin: `VaultCrypto` (seal / open / derive),
  `VaultSecret` (PIN and passphrase rules), `VaultLock` (delays, auto-lock, clipboard time), `VaultHeader` (the clear
  part), `VaultIndex` (items, folders, crumbs, guard, move without loops, delete a subtree, search without accents),
  `VaultTemplates`, `VaultStore` / `VaultSession` (the folder on disk, atomic writes, unlock, files, change of code,
  options, export / import), `VaultBackup` (the file format).
- `feature-vault` — `VaultKeys.kt` (the two Keystore keys, the prompt, the availability check for Android 9 / 10 / 11+),
  `VaultFeature.kt` (state, auto-lock through the activity callbacks and `ACTION_SCREEN_OFF`, file import, camera,
  open elsewhere, backup / restore, clipboard), `VaultScreens.kt` (setup, lock, the key-lost screen, list with crumbs
  and search, item, editor, guard, settings).
- The catalogue: `Catalogue.VAULT` (`vault`, 🔐, Munka, BETA, M24); `vrg://vault` opens it; Kommand finds it.
- `kit/res/xml/file_paths.xml`: `cache/vault-out/` for the FileProvider (the camera photo before it is sealed, and
  ↗ Megnyitás).

## Telefonon ellenőrizni

1. Széf tile → "Új széf": a weak PIN (123456, 111111) is refused with its reason; a good one creates it. With a
   fingerprint enrolled the prompt asks right away to turn it on.
2. + Új → ▸ Mappa "Ügyfelek" → in it, 👤 Ügyfél: fill name, address, kapukód → Mentés. The kapukód shows ••••; 👁 shows
   it; ⧉ copies it, and after 30 s the clipboard is empty.
3. + Új → 📎 Fájl (a PDF), and 📷 Fotó: both appear with their size; the photo shows in the Széf; the PDF opens with ↗
   Megnyitás in a PDF app. After 🔒 the app can no longer open that copy.
4. Keresés: the client's town without accents finds it; the kapukód does not.
5. Screenshot while the Széf is on screen → refused; Recents shows a blank card. Leave the Széf → screenshots work again.
6. Screen off and on → locked. Set "30 mp", go to another app for 40 s → locked; for 10 s → still open.
7. Fingerprint unlock; "PIN-kód" in the prompt → back to the PIN field. Enrol a new fingerprint in Android → the Széf
   says it opens with the PIN only; Beállítások → turn it on again.
8. Five wrong PINs → "várj" with a countdown. With "10 hibás próba után törlés" on (on a test vault!) the 10th deletes it.
9. Mark the folder "Megnyitáskor újra azonosítás": opening it asks again; after 🔒 and unlock, it asks again.
10. Áthelyezés (a folder cannot go into itself), Törlés of a folder with a file in it.
11. Beállítások → Kód cseréje (PIN → jelmondat), lock, open with the new one.
12. Mentés fájlba → a `.vrgvault`; Széf törlése; a new Széf; Visszaállítás mentésből with the password → everything
    is back, the photo and the PDF included. A wrong password is refused.
13. TalkBack: the lock screen and the list are readable; the masked values are not read out.
