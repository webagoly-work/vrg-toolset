# M6 · Gyorsjegyzet (`notes`): notes into the chat-log branch

**Goal.** Type, dictate or share a note on the phone, and it lands in a dedicated branch of the repo that acts
as the project's chat log. Sessions and the user can read it from anywhere. Answer D-6 first. The recommended default is A:
branch `mobile-log`, one file per day `log/YYYY-MM-DD.md`.

## Build

- `kit-core`: the note model and its Markdown line
  (`- 14:32 · [planner] szöveg… (from: phone, branch: <active branch>)`), plus the append rule (read the day file + sha,
  append, PUT with sha; on a 409 / sha mismatch, re-read and retry up to 3 times). Tests.
- `kit` GitHub client: contents GET / PUT, and creating the `mobile-log` branch from `main` if it is missing
  (`POST /git/refs`). Never write to any other branch: the branch name is a constant, and the client refuses others.
- `feature-notes`: a text field with 🎤 dictation (hu-HU), a tag picker (the tools from M4's map), an
  outbox that queues offline and sends when online (WorkManager), and today's log read back.
- Share target: "Megosztás → VRG Mobile" with text from any app creates a note.
- `vrg://notes/new?text=…` (already routed by `Links`) pre-fills it.

## Tests (cloud)

The Markdown format, the append-with-retry logic against a fake API (conflict once, then OK), the outbox order.

## Phone check (2026-10-31, Redmi Note 13 Pro 5G, Android 15, a VPN running)

- Online note: **pass.** `teszt online` landed at once and created `mobile-log`.
- Offline note: queued correctly with "Nincs internet.", landed once and with its own time, but **4 h 10 min after the
  network came back** (07:33 → 11:42). A bug, fixed below; the fix still needs its phone check.

**What happened.** The phone was locked with the app's process alive. The phone reported the app as
`blocked=APP_BACKGROUND`, yet WorkManager ran the worker in that process (`GreedyScheduler`), each try failed in about
20 ms and came back `RETRY`, and the exponential backoff stretched 30 s into hours. `api.github.com` answered from the
phone the whole time. The blocked network is the likely cause, not a proven one: the exception was swallowed, so
`GitHub.call` now logs it (Logcat tag `VRG/github`). "Küldés most" could not help either: it called `schedule()`, and
`KEEP` leaves a waiting retry as it is.

**The fix.** `VrgFeature.onAppVisible()` (the shell calls it on every resume) tries the outbox directly, "Küldés" and
"Küldés most" do too, and the backoff is LINEAR. A note written while the phone is locked for good can still wait for the
next time the app is opened or for a retry; a share into the app sends at once.
