## 3.3 "Seeing parts of memory reached by a process"

This is the hard one, so the answer is split into what "reached" can mean.

| Question | Available? | Source | Result on this PC |
|---|---|---|---|
| How much RAM does it hold now? | **Yes** | Working set in the process snapshot | All 415, 1 s |
| How much of that is private vs shared? | **Yes** for processes we can open | Private bytes; `QueryWorkingSetEx` per page | Openable: 254–261 of 415 |
| What does its address space look like? | **Yes** for processes we can open | `VirtualQueryEx` | Spike on one shell: 1 646 regions in 4 ms, split into image, mapped, private, reserved |
| Which of its pages are in RAM right now? | **Yes** for own processes | `QueryWorkingSetEx` by page | Costly on large processes; on demand only |
| Is it paging in from disk? | **Yes**, with ETW | Hard-fault events (system total without ETW) | Tier B |
| What is the machine's memory mix? | **Yes** | Page-list counters | Standby, Modified, Free and Zero, pools, all readable |
| **Which physical address does it use?** | **Not unelevated** | PFN database through the undocumented `SystemSuperfetchInformation` query, which RAMMap uses; admin required | Not attempted |
| **Which bytes did it actually touch just now?** | **No** | The CPU does not report this to user mode, and accessed bits are not exposed | Not available in any practical tier |

Three reasons the physical view is not what the user wants, even if it could be had:

1. **Physical placement is arbitrary.** The memory manager hands out free pages from a list, so one program's pages are
   scattered across the DIMM on purpose. A truthful map is uniform noise.
2. **It moves.** Pages are trimmed, written out and returned to different frames while being watched.
3. **Being resident is not being touched.** A page in the working set may not have been used for minutes. Neither
   working set nor PFN data shows access; a cache hit never leaves the CPU, and no OS counter sees it.

**So the view shows this instead, and says so:**

- **The market square is schematic.** Lot positions carry no address. The legend states: *"A telkek helye jelkép, az
  arányok mértek."* (Lot positions are symbolic, the proportions are measured.)
- **The market's mix is exact:** program stalls, shared, kernel, Modified, Standby, Free.
- **A program's stall size is exact**, updated once a second, and it visibly grows and shrinks.
- **Telekkönyv, the real thing:** select a program and a panel draws its true address space as a strip of real regions
  (image, DLLs, heaps, stacks, mapped files, reserved) with real sizes. This is the closest honest answer to "parts of
  memory", and it is more interesting than physical frames, because the regions have meaning: you can see the DLLs it
  mapped and how much is reserved but never used.
- **Reach, as a rate:** dump trucks show hard faults, so "it just had to fetch memory from disk" is visible with ETW.
- **Later, if wanted** (CITY-D44 B): a RAMMap-style physical view is possible later through the elevated sidecar.
  It would be a curiosity, and it relies on an undocumented interface, so it is not recommended.

## 3.4 Other things that cannot be seen

| Keystrokes, window titles, command lines, file names in the page | **Refused on principle**, CITY-D27 A | Classes and counts only |

## 3.5 Finding: ETW is off, for two separate reasons

Both reasons need the user. Claude changes neither (CITY-D17 A).

1. **The scheduled task cannot start.** Its action reads as program `C:\Program` with argument `Files\VRG\...`, because
   the path lost its quotes. Last run 2026-10-27 02:51, result `0x80070002` (file not found). The pipe does not exist, so

   the re-root. It would start, but its file filter would match nothing under `H:\VRG\Full`. The network and process
   parts would work. `node CodeCity/tools/build-etw.js` rebuilds it with the right path, and the user reinstalls it with
   `install-etw.ps1`.

The Kódváros README's "checked 2026-10-27" stays true for its moment, but this has been silently broken since. The fix
steps are in [04-data-feed.md](04-data-feed.md) §4.7. Homeland does not depend on it: everything marked ETW falls back or
