# Rajztár: the drawing and document data store

The offline knowledge base behind VRG's electrical document generator. It holds the rules a professional Hungarian
electrical design package follows, from one distribution board to an industrial site: what documents exist, what
each must contain, how a sheet looks (paper, frame, title block, lines, lettering), how devices, circuits and cables
are named, and a symbol library drawn on one geometry. Every program (Planner, Workflow Kit, a future document
engine) reads the JSON files. Nothing is fetched at run time.

```
shared/rajztar/
  data/sources.json      laws, chamber rules, operator rules, standards (ids used everywhere else)
  data/documents.json    phases · project classes · 37 document types (need matrix, content, rules) · packages
  data/formats.json      PDF/A output · ISO 5457 sheets · MMK/ISO 7200 title block (+ layouts) · revision table
                         · ISO 128 lines · ISO 3098 lettering · ISO 5455 scales · numbering · layers · colours · legend
  data/conventions.json  IEC 81346 reference designations · board names · circuit labels · device descriptors
                         · IEC 60445 conductor colours · HU cable types · HD 60364-5-52 installation methods
                         · earthing systems · zones (bathroom, LPZ, Ex) · IP/IK · HU switch codes · renovation states
  data/symbols.json      155 symbols (GENERATED, do not edit)
  src/symbols.src.js     the symbol source: shared geometry helpers + every symbol
  src/render.js          symbol → SVG, title block layout → SVG (Node and browser)
  build.js               validate everything, emit symbols.json, render catalog.html
  catalog.html           the visual catalog (GENERATED; open from disk, no server needed)
```

## Rajztár Stúdió (`studio.html`, START P → J)

One offline file, generated by `build.js` from `src/studio.html` + `src/studio.js` + the data:

1. **Csomag**: project data and the MMK §4 people. You pick a project class, a phase, the levels and the conditions
   (permit, fire alarm, emergency lighting, lightning, PV, EV, renovation, MV, automation). It then builds the
   drawing register from `documents.json`:
   - numbered `V-101`, `VG-103`, …;
   - one plan per level;
   - the missing mandatory sheets counted;
   - a printable A4 tervjegyzék (MMK 12.2.2).
2. **Lap**: an ISO 5457 sheet at true millimetres. It has a frame with the 20 mm filing margin, centring marks and
   grid zones, the `mmk-180x62` title block filled from the project, and a revision table above it. A legend lists
   only the symbols actually used (or points to a separate legend sheet), and plans get a scale bar. You can:
   - place symbols, draw ISO 128 lines (click points; a second click on the last point or Enter closes) and write text;
   - snap everything to the 2.5 mm grid;
   - rotate (R), delete (Del) and nudge (arrow keys);
   - print to PDF at the sheet's own paper size, or save SVG.
3. **Jelek**: the symbol editor. The body markup is edited with a live 0.5 / 2.5 mm grid preview, a real-size view,
   ports added by clicking, and a lint that runs the build's checks. Edits live in the project, and the Lap tab uses
   them at once. To bring them into the library, export `symbols.overrides.json` into `data/` and run `build.js`,
   which validates the edits and merges them over the source.

State is kept in localStorage when served over http, and always in the exportable project file (`*.rajztar.json`).
`file://` gives no storage, so export before closing.

```bash
node shared/rajztar/test/studio-e2e.js [--shots <dir>]   # 32 checks in headless Chrome, real mouse/keys
```

## Build and check

```bash
node shared/rajztar/build.js           # validate + regenerate symbols.json and catalog.html
node shared/rajztar/build.js --check   # validate only (exit 1 on error)
```

The checks cover: every `basis`/`std.ref` names a known source, every document has a `need` value for each project
class and a `cond` where the value is C, packages name real documents, symbol ids are unique and prefixed by their
category, ports lie inside the box and (for schematic devices) on the 2.5 mm module grid, title-block cells fit the
180 mm ISO 7200 width, and every MMK §4 A–H field has a cell in the standard layout.

## Where the rules come from

The primary formal source is the **MMK Tervdokumentációk tartalmi és formai követelményeinek szabályzata (2017)**,
read in full for this round: §3 sheets (PDF/A, scale, legend), §4 title block fields A–H, §7 permit-stage electrical
part (a technical description only), and §12 construction-stage electrical part (12.3 low-voltage power, 12.3.3
lightning, 12.4 MV, 12.5 low-current, 12.6 automation). Metering and connection rules come from the MEE-VET guide
on design duty and exclusive custody (2025-07-23), which rests on 40/2017 NGM, 18/2017 MEKH and MSZ 447:2019.
`sources.json` marks each source `verified` (with the URL checked on 2026-11-17) or `knowledge` (edition and
clause to be confirmed before a document cites it as binding).

## Symbol confidence

Each symbol says how sure its drawn form is: `iec` (the IEC 60617 form), `iec-approx` (right family and meaning,
our proportions), `hu-practice` (no single IEC form; drawn as Hungarian plans usually show it), `vrg` (our own,
always explained in the legend). IEC 60617 S-numbers are deliberately left empty until they are checked against
the IEC database, so none is invented.

## Relation to the Planner

The Planner's own symbol set (`05z-icons.js`) is a screen-first design language (body = family, mark = device,
colour = system). The Rajztár is the standards-true print set for official documents. Standard mounting heights
are not duplicated: `conventions.json` points at the Planner's `STD_H` table as the single source.
