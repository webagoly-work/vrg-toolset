3.3 V logic everywhere

Every blade and module here runs 3.3 V I/O. Nothing in this book needs a level shifter. Power I²C modules from the console's 3V3 pin, never from 5 V.

One supply per board

A board gets power from its 5V pin or from USB, never both. Unplug the rail before you plug a blade into a PC.

Common ground

Every GND in a stage is one net. Any board that shares a signal wire must also share ground.

Boot pins differ

Download mode is GPIO9 low on C3, C6 and C2, and GPIO0 low on the WROOM-32D. On the ETH01-EVO, GPIO9 is also the Ethernet chip-select.

Shelf node

One ETH01-EVO on the router serves a static page from its flash. The board has no USB-serial chip, so the first flash goes through a CH343P harness; after that, updates go over the network (OTA).

EDGE firmware pins
// ETH01-EVO · on-board DM9051 wiring (fixed, not on the header)
#define ETH_PHY_TYPE   ETH_PHY_DM9051
#define ETH_PHY_ADDR   1
#define ETH_CS         9    // also the boot strap
#define ETH_IRQ        8
#define ETH_RST        6
#define ETH_SCK        7
#define ETH_MISO       3
#define ETH_MOSI       10
#define ETH_SPI_MHZ    8    // community-tested speed; raise later if stable
#define LED_LINK_A     2    // on-board LED, active low (1k to 3V3)
#define LED_LINK_B     5    // on-board LED, active low

// Arduino-ESP32 3.x — check the ETH.begin() signature against your core:
ETH.begin(ETH_PHY_TYPE, ETH_PHY_ADDR, ETH_CS, ETH_IRQ, ETH_RST,
          SPI2_HOST, ETH_SCK, ETH_MISO, ETH_MOSI, ETH_SPI_MHZ);

Before power-on

  • CH343P logic jumper on 3.3 V.
  • Supply set to 5.0–5.2 V, measured before connecting.
  • Nothing on header pins 1–2 (PoE). This board must never see passive PoE from this build.
  • Flash once with BOOT held through a RESET tap; confirm the page opens on your LAN, then enable OTA.
V0.3

Console

A C3 Zero becomes the console: it listens to the blades over ESP-NOW, shows the leader and uptime on the OLED, and keeps a boot/crash log in the EEPROM. EDGE-A from V0.2 stays wired as it was.

  • AT24C256 EEPROM module
  • Same 5 V supply and breadboard

To buy

CONSOLE firmware pins
// CONSOLE · ESP32-C3 Zero
#define I2C_SDA   4
#define I2C_SCL   5        // Wire.begin(4, 5, 400000)
#define ENC_A     6        // INPUT_PULLUP
#define ENC_B     7        // INPUT_PULLUP
#define BTN_PUSH  3        // active low
#define BTN_BACK  1        // active low
#define BTN_OK    0        // active low
#define RGB_LED   10       // on-board WS2812
// never use: 2, 8, 9 (strapping) · 18, 19 (USB) · 20, 21 (UART0 log)
#define OLED_ADDR 0x3C     // SH1106 driver, not SSD1306
#define EEP_ADDR  0x50

Before power-on

  • OLED and EEPROM VCC on the C3 Zero's 3V3 pin, not 5V.
  • The 1.3" module uses the SH1106 driver; an SSD1306 library gives a 2-pixel shifted image.
  • Module silkscreen names vary (TRA/TRB/PUSH or A/B/SW). Match by function. If your encoder header has its own GND/COM pin, tie it to GND.
  • Run an I²C scan: expect 0x3C and 0x50 only.
V0.4

Duo

A second ETH01-EVO joins. The two edges elect a leader over ESP-NOW and the winner answers on the shared address. The PCF8575 gives the console a hard-reset line to each edge, so it can recover a hung blade during failover tests.

From stock

  • ETH01-EVO ×2 (1-2-39) → EDGE-A, EDGE-B
  • PCF8575 module
  • Console from V0.3
  • Second patch cable

To buy

  • Nothing (uses two router LAN ports)
V0.4 firmware additions
// CONSOLE additions
#define PCF_ADDR   0x20
#define RST_EDGE_A 0       // PCF P00
#define RST_EDGE_B 1       // PCF P01
// reset pulse: pcf.write(pin, 0); delay(100); pcf.write(pin, 1);

// both edges: ESP-NOW and Ethernet together
//  WiFi.mode(WIFI_STA);  esp_wifi_set_channel(CH, WIFI_SECOND_CHAN_NONE);
//  CH = your router's fixed 2.4 GHz channel (1, 6 or 11), same on every blade

Before power-on

  • PCF8575 address pads A0–A2 to GND (many modules ship this way). Scan should now show 0x20, 0x3C, 0x50.
  • Fix your router's 2.4 GHz channel. ESP-NOW only works when every blade sits on the same channel.
  • Both edges get their own MAC; only the elected leader claims the shared IP.
  • Total draw about 0.5–0.7 A. Check it with the KWS-065C meter or the supply's display.
V0.5

Swarm

The rest of the uncontested boards join over ESP-NOW. Workers need only power; the WROOM-32D becomes the store with the microSD card; the C6 pair are Wi-Fi backup edges. This is also where the compute branch forks off.

From stock

  • ESP32-C3 Zero ×5 → W1–W5
  • ESP32-C2 DevKit → W6
  • ESP32-C6 DevKit ×2 → backup edges
  • 20 AWG silicone wire for the 5 V strip
  • M3 brass standoffs for the rack

To buy

#define RST_C6A   3        // PCF P03
#define RST_C6B   4        // PCF P04
// C3 Zero workers have no EN pin: recover them with the task watchdog.

Before power-on

  • Estimated load 1.3–1.8 A average with peaks above 2.5 A. This is the 3 A supply's limit; move to V1.0's split rails before adding anything else.
  • If your C2 board breaks out EN, wire it to PCF P05. If it doesn't, leave P05 free.
  • Format the card FAT32 before first boot.
  • Bring blades up one at a time and watch the console count them.
V1.0

VAULT

Everything moves onto the standoff rack with two fused, metered 5 V rails, the DS3231 for wall-clock time at boot, and INA219 telemetry on the console. Public HTTPS goes through a router port-forward to the elected edge.

From stock

  • Everything from V0.5
  • 180 W dual-output PSU (7-3-44)
  • LM2596 buck (7-1-52)
  • W3230 thermostat for a rack fan (optional)

To buy

  • DS3231 module (ZS-042 type)
  • INA219 module ×2
  • 2 A fuses + holders ×2

V1.0 I²C address map
// CONSOLE · full I²C map (400 kHz)
#define PCF_ADDR    0x20
#define OLED_ADDR   0x3C
#define INA_A_ADDR  0x40   // rail A: edges, store, console
#define INA_B_ADDR  0x41   // rail B: workers
#define EEP_ADDR    0x50   // AT24C256 · boot counters, election log
#define RTC_EE_ADDR 0x57   // 24C32 on the DS3231 board (spare log space)
#define RTC_ADDR    0x68   // DS3231 · wall clock for TLS at boot
// INA219 calibration: 0.1 Ω shunt, 3.2 A range (Adafruit default)

Before power-on

  • Read the 180 W PSU's output label first. Use its 12 V output into the LM2596, or skip the LM2596 if it has a 5 V output.
  • Trim the LM2596 to 5.10 V with no load connected.
  • ZS-042 boards try to charge the coin cell. With a plain CR2032, remove the charging resistor or cut its trace.
  • Pull-ups add up across 7 modules (about 1.3 kΩ total). If the bus misbehaves, remove the pull-ups on one or two modules.
  • Run the CGNAT check before opening the port-forward.

Compute branch · no new wiring

The swarm experiments run on the V0.5 / V1.0 wiring as it stands. Each C3 Zero's on-board RGB LED (GPIO10) shows its job state, so the rack itself becomes the progress display.

  1. X1 Tile farm. Fixed-point Mandelbrot tiles over ESP-NOW; tiles render on the console OLED.
  2. X2 Fault tolerance. Pull a worker's power mid-job; the job still finishes through work stealing.
  3. X3 Search jobs. Integer prime or hash search, the best fit for the C3s.
  4. X4 Coupled sim. Cellular automaton with neighbour exchange, to find the radio's limit.
  5. X5 Live job page. The elected edge serves a page that submits jobs and shows the tiles filling in.

Keep compute tasks at a lower FreeRTOS priority than heartbeats and the election. The C3 is single-core, and a starved heartbeat looks like a dead blade.
