VRG Overhaul Plan

The parts are good. The trouble is that there are too many front doors, names, lists and search boxes, and they disagree with each other. A professional version is mostly about consolidating: one name, one registry, one command bar, one window model and one visual kit, with every surface built from the catalog.

01Verdict

The foundation is already professional-grade in places. The overhaul is a consolidation project, not a rewrite.

Keep and build on

  • The catalog as the single registry. Every surface sends a catalog id to one resolver (shell/lib/catalog.js:143). That is the right architecture; it just isn't used everywhere yet.
  • The UI kit. Four themes, three densities, 161 icons, an action registry and verified contrast. It is better than any single app's own look.
  • The level model (User / Dev / All). It is the right way to hide workshop tools from daily use.
  • The guard rails: check-start, check-catalog, per-package tests, the exe selftest.

What holds it back

  • Duplication. The same tool can be reached 9 ways under different names; the level switch is in 5 places.
  • Two eras live side by side: the old Kezdőlap next to the new Dashboard view, Munkapad next to Lapok, Toolbox and Zen next to the catalog.
  • The workshop shows through. START keys, ports, layer letters and raw English status words appear at User level.
  • Unfinished edges: no focus styles, silent failures, settings that say "edit the JSON".

02Findings

Eleven problems, most severe first. Each says what you feel when using it, where it comes from, and the standard a professional program meets.

F1

One program, about ten nameshigh

The window says "VRG Asztal", the taskbar says "VRG Irányítópult", the exe is "VRG Desktop", and two different screens are both headed "Irányítópult".

Evidence: vrg-desktop.html:6,75 · main.js:89 · tray.js:48 · desk.js:380 · vrg-dashboard.html:204 · AppUserModelId VRG.Dashboard. Panes have the same issue: the chat pane is "Claude", "Claude chat", "Chat" and "Claude oldalchat"; the feed is "Hírfolyam" and "Hírek".

StandardOne product name, one name per view, one name per pane, stored once (in the catalog) and read by every surface.

F2

Seven lists of toolshigh

A tool added in one place is missing in another. You learn several maps of the same territory.

START, the Kapu list, Toolbox, the Zen presets, the Desktop catalog, the Console catalogue and the Mobile tools.json (ARCHITECTURE.md:9-19). The Planner alone is reachable from START 1, START P/W, Zen 2, a Kapu row, a tile, the dock, a dial, a sheet preset and the palette. The Kapu still says "Irányítópult — készül" and has no link to the Desktop (90-gate.js:158).

StandardOne registry, many renderers. START, Kapu and Mobile are generated from vrg-catalog.json, and a check fails when anything else lists tools.

F3

Ten places to search, three shortcutshigh

You have to remember which box finds which kind of thing. Ctrl+K works in every app but not in the shell.

The shell palette is Ctrl+Shift+P and searches START acts and panes but not catalog items (palette.js:96-119). The Quick bar (Ctrl+Alt+K) shows one preview line and no result list (quick.js:17). There is also an internal search (Ctrl+Shift+F), the dial's type-to-search, the Lapok picker, three section filters, the Kezdőlap "/" box and the Stack search page. Ctrl+Alt+K is also claimed globally by the Kódváros overlay (CodeCity/shell/main.js:21), a real clash.

StandardOne command bar on Ctrl+K that searches everything (apps, actions, files, Stack, settings) and narrows by prefix or tab. Other boxes filter only the list in front of you.

F4

Two window models at oncehigh

Windows sometimes land on the Lap grid and sometimes in the old split workbench, and the same keys do different things in each.

Munkapad (split tree, WP-34) and Lapok (4×4 sheets, WP-46) coexist. A full Lap silently diverts the new window to the Munkapad (frame.js:401). Ctrl+Alt+arrows mean "focus pane" on one and "maximise / switch sheet" on the other (layout.js:144 vs sheets.js:595). There are three ways to save a layout: Munkaterek, sheet templates, Zen sessions.

StandardOne window model with one set of keys, and one way to save a layout. When the space is full, say so and offer a choice.

F5

The look is fragmentedmedium

Moving between apps changes fonts, theme names, header styles and keyboard habits. The corner dials are light glass on a dark desk.

The kit is inlined only in the Kapu. Planner, Inventory, the calculators, MindMap and BuildTree carry copied Mélyvíz CSS. MindMap has 5 themes of its own, BuildTree 4, Console its own "Varler SUI" chrome, and the Valena picker is plain white. The shell has no theme or density switch (desk.css:2-9). Symbols are drawn ad hoc per page; see §04.

StandardEvery app takes its chrome (header, command bar, status bar, dialogs, toasts, focus, themes) from one kit version. Visualisations (Kódváros, Gömb, Térkép) may keep their own canvas.

F6

Everything is said twice, and in workshop languagemedium

Labels are doubled ("nyitott munka · open jobs"), and the User view still shows things only a developer understands.

Bilingual pairs are everywhere (desk.js:152-155). Raw English status words ("beta", "dev") and level codes appear on tiles (desk.js:131-133). Jargon on User screens: "START P/B", ":8131", layer letters F/I/Q, "Kontextuscsomag", "Munkapad" vs "Lap". Overloaded words: "Keresés" opens two different things; "Munka" means five; "Indítópult" means START in the Kapu and something else on Mobile; icon codes TB, A and Z each name two things.

StandardHungarian interface, English as a language setting rather than a second line. One glossary; User level never shows ports, keys, ids or file paths.

F7

Silent failures and dead endsmedium

You click and nothing visible happens, or a tile is greyed out with no reason.

Tiles that resolve to nothing are just disabled (desk.js:129), e.g. Értesítések and three dev-root categories. START-only items toast "Ez a START-ban fut" (desk.js:100). Opening a server item can wait up to 10 s with no busy state (main.js:781). ◢ "F · Kiemelt" loops back to the Dashboard; "Z · Kódex" is permanently disabled. Job rows without an action ignore the click (desk.js:166).

StandardEvery action shows pressed → working → done/failed. A disabled control says why and what would enable it. Nothing on a User screen is a dead end.

F8

Keyboard and screen-reader gapsmedium

With the keyboard you lose track of where you are; some things can't be reached at all.

No :focus-visible on tiles, level buttons, top strip, section anchors, sheet buttons, the palette list (which sets outline:none) or the window bar (desk.css:22,147,201,211,301; vrg-desktop.html:17,47). Katalógus rows are clickable <tr>s; Kezdőlap chips are clickable <span>s. Dialogs don't take focus or label themselves (desk.js:463). Toasts have no aria-live (toasts.js:28). A double Tab on any control toggles the view, so fast keyboard use triggers it by accident.

StandardWCAG 2.2 AA: everything reachable and visible by keyboard, proper roles for palettes, lists and dialogs, live regions for toasts, view switching on an explicit chord.

F9

Layout breaks on real datamedium

Parts of the Kezdőlap become unreadable once the repo grows.

The Repó card lists every local branch inline, about 90 lines today. The Indító panel's names wrap one letter per line. The Ma panel shows 20+ stale reminders with identical buttons and no grouping. See §03.

StandardEvery list has a cap, a "show all" and an empty state; every text cell has min-width:0 and truncation. A visual test renders the page with today's real data.

F10

Settings are a JSON filelow

To change a shortcut or pin a dock item you edit files by hand.

The Beállítások sheet has one live control (level); the rest is text that points at Dashboard/config/keymap.json (desk.js:492-498). Dock pins exist as a setting with no UI. The documented default window mode (Munka) differs from the code's (ablak, winmodes.js:34).

StandardA real settings screen: appearance, language, level, keys, dock, start view, startup behaviour, with reset to default.

F11

It doesn't yet ship like a productlow

The exe has Electron's icon. Today's build failure showed the other weak point: building from the wrong checkout quietly points the exe at stale code.

The icon is waiting on rcedit (DESKU-Q12). package.js writes whatever checkout it runs from into vrg-desktop.json; a run from wt-desktop-unify made the exe show a Dashboard about 3,400 lines behind main. There is no version number, About screen, changelog or crash log.

StandardOwn icon and version, About with the commit it runs, a build guard (main checkout, clean tree, exe closed first), a log file, and a one-step reinstall.

07Roadmap

Seven phases, in order. Sizes are rough sessions of work. Each phase ends with a check that proves it is done, so the next one starts on solid ground.

P0

Repair what is visibly broken

1–2 sessions
  • Fix the Repó branch list (cap at 8 plus "+82 more") and the Indító one-letter wrap.
  • Add :focus-visible to every shell control; aria-live on toasts; a reason on every disabled tile; a busy state on slow opens.
  • Resolve the Ctrl+Alt+K clash; move the shell palette to Ctrl+K.
  • Build guard in package.js: refuse a non-main checkout unless --repo is given; close or ask before overwriting a running exe.

Done whena headless screenshot with real data shows no overflow, and a keyboard pass reaches every control with a visible focus.

P1

Names and one registry

2–3 sessions
  • Decide the names (see §09) and apply them everywhere from the catalog.
  • Generate the Kapu list, the START main screen and Mobile tools.json from the catalog.
  • Retire Toolbox and the Zen sessions; fold the Kezdőlap's useful cards into the Áttekintés and retire it.

Done whencheck-catalog fails on any tool list outside the catalog, and every surface shows the same name for the same item.

P2

One command bar

2 sessions
  • Ctrl+K searches catalog items, actions, panes, files, Stack nodes and settings, with tabs and prefixes.
  • The Quick bar becomes a mode of it; section filters stay as list filters only.
  • A results list with keyboard roles (combobox/listbox) and recent items first.

Done whenevery catalog item opens from Ctrl+K in three keystrokes or fewer (a test walks all 94).

P3

One workspace

3 sessions
  • Keep Lapok as the model; splits live inside a cell; the Munkapad's saved trees convert to templates.
  • One key set for windows; an explicit view chord in place of the double Tab.
  • A settings screen: appearance, language, level, keys, dock pins, start view, startup.

Done whenno code path opens into the Munkapad, and nothing in Beállítások says "edit the file".

P4

One visual system

1 session per app
  • Kit v1.1: the Symbols and indicators family, a "Terep" theme for Console, dark-glass dials.
  • Adopt it app by app, most-used first: Planner, Készlet, Kalkulátorok, MindMap, BuildTree, Archívum, Console.
  • A drift test per app, as the Kapu already has.

Done whenevery app reports the same kit version, and the theme switch in the shell changes every open app.

P5

Language and accessibility

2 sessions
  • A strings table per app; Hungarian by default, English as a setting; remove the side-by-side pairs.
  • An automated accessibility check (axe-core, vendored and pinned) in each app's tests, plus a manual keyboard and screen-reader pass.

Done whenWCAG 2.2 AA checks pass in every app, and no User screen shows English unless English is chosen.

P6

Ship it like a product

2 sessions
  • Own icon (vendor rcedit), version number, About screen with the commit, a changelog from the commits.
  • A log file and a "copy diagnostics" button; a portable zip or installer for the OTG kit.
  • Visual regression: headless screenshots of every view at User / Dev / All, compared on each build (chrome-headless-shell is already in tools).

Done whena fresh machine runs the Asztal from the OTG kit, and a build that changes a screen shows the change before it ships.

08The professional bar

A checklist to hold every part against. A part is professional when every line is true for it.

Clarity

  • One name, used the same way everywhere
  • One way in for each job; the others redirect
  • No internal ids, ports or paths at User level
  • One language per screen

Behaviour

  • Every action gives feedback within 100 ms
  • Every failure says what happened and what to do
  • Every list has a limit, a "show all" and an empty state
  • Nothing is lost: undo, or a confirmation that names what changes

Consistency

  • Chrome, themes and symbols from one kit version
  • Ctrl+K, Esc, Ctrl+W mean the same in every app
  • Same symbol, same meaning, everywhere
  • Settings in one place, editable in the UI

Craft

  • Visible keyboard focus, proper roles, live regions
  • Contrast checked in every theme
  • Screenshot tests with real data
  • Version, About, log and icon on the exe
