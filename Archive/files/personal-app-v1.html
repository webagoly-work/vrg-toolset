The short answer

Where we stand

VRG Mobile is already most of a personal app.

It has one shell, a feature catalogue kept as data, its own device trust, self-update and a relay to the PC. What it lacks is the person: every tile today serves the VRG work, and nothing serves the rest of the day. The Varler Console PWA and the desktop-only tools hold most of the missing everyday pieces.

Recommendation

An edition is a filter over the same app.

The catalogue (kit-core/Feature.kt) already carries each feature's group, stage and needs. Add an editions set and a home layout per edition. General and Founder then become two views of one APK, one codebase and one update channel. Give General its own app id only if it is ever handed to someone else.

The two editions

General: one person, any trade

No VRG PC and no client data. It has to make sense on its own and install and work with nothing else. Rule: nothing in the default needs the relay or a GitHub sign-in. Both are opt-in packs.

Opt-in packs

What General still lacks

  1. Storage on the phone first. Today notes and most work data live on GitHub or the PC.
  2. Export and import of everything as plain files: the condition for nothing being lost when the app is.
  3. A first start without GitHub.
  4. An edition filter in the catalogue and a home layout per edition.
  5. The request loop for everything: GO VARIANT widened from Sketcher variants to "make me a page".
