1 · Definition1 · Meghatározás

What it isMi ez

The VRG Stack is one graph of the whole VRG work, cut into layers, a kind of multilayer network. Each layer is one way of seeing the same body of work: what exists, why, who did it, what changed, where it lives, how it is reached, whether it works and what is wrong. Vertical links join the same real thing across layers.

A VRG Stack a teljes VRG-munka egyetlen gráfja, rétegekre bontva: egyfajta többrétegű hálózat. Minden réteg ugyanannak a munkának egy-egy nézete: mi létezik, miért, ki csinálta, mi változott, hol van, hogyan érhető el, működik-e, és mi a hiba. A függőleges kapcsolatok ugyanazt a valós dolgot kötik össze a rétegeken át.

The idea that carries it is the String (Füzér). Pick anything on any layer and follow its vertical links. The set of layers it reaches is its reach mask, and the mask is the thing's development state. Nobody types the state in; it falls out of the data.

Az egészet egy ötlet viszi: a Füzér. Válassz ki bármit bármelyik rétegen, és kövesd a függőleges kapcsolatait. Az elért rétegek halmaza az elérési maszk, és ez a maszk maga a dolog fejlettségi állapota. Az állapotot senki nem gépeli be; az adatokból adódik.

2 · Mechanism2 · Működés

How it worksHogyan működik

sources→adapter per layer→join→record · runs→pillars · validate→analytics→signals→graph · events · index→page data · reports
források→rétegenként egy adapter→összekapcsolás→rögzítés · futások→pillérek · ellenőrzés→elemzés→jelzések→gráf · események · index→oldaladatok · jelentések

The analytics stage ranks nodes with PageRank, finds communities with the Louvain method, spreads attention with spreading activation and mines repeated step orders with PrefixSpan.

Az elemzés a csúcsokat PageRankkel rangsorolja, a Louvain-módszerrel közösségeket keres, terjedő aktivációval osztja szét a figyelmet, és PrefixSpannel bányássza az ismétlődő lépéssorrendeket.

Guarded buildVédett build

A failing layer is carried forward from the last good build, so it never empties. Optional stages are skipped. Writes are atomic under one lock. out/ is disposable; data/ is append-only, bitemporal history.

Egy hibázó réteg az utolsó jó buildből öröklődik, így sosem ürül ki. A választható lépések kimaradhatnak. Az írások atomiak, egyetlen zár alatt. Az out/ eldobható; a data/ csak bővülő, bitemporális történet.

Live twin · S5Élő iker · S5

A digital twin of the work. A source map knows which layer each file feeds. A hand edit re-runs one adapter, the rest comes from the layer cache, and a test proves the result equals a full build. Open pages reload in about a second.

A munka digitális ikre. Egy forrástérkép tudja, melyik fájl melyik rétegbe táplál. Egy kézi szerkesztés csak egy adaptert futtat újra, a többi a rétegtárból jön, és egy teszt igazolja, hogy az eredmény azonos a teljes builddel. A nyitott oldalak kb. egy másodperc alatt frissülnek.

Page contract · S7Oldalszerződés · S7

Every page signs the page contract. Select something on one page and every other open page lights that thing's string in its own vocabulary. A lint test holds all pages to it.

Minden oldal aláírja az oldalszerződést. Ha egy oldalon kiválasztasz valamit, a többi nyitott oldal a saját nyelvén világítja ki annak füzérét. Egy lint-teszt minden oldalt ehhez köt.

Write gateway · S6Íráskapu · S6

The one write path, the gateway. It previews the exact diff, applies it only if the file is unchanged and its own parser reads the result, logs an event, and never commits.

Az egyetlen írási út, az íráskapu. Megmutatja a pontos eltérést, csak akkor alkalmazza, ha a fájl nem változott és a saját értelmezője helyesen olvassa az eredményt, eseményt naplóz, és sosem commitol.

Stack Viewer · S8–S10Rétegverem-néző · S8–S10

The Stack Viewer: WebGL planes filled with a particle system made from each layer's own text, about one particle per 16 bytes, laid along a Hilbert curve, with a time scrubber and a live diff glow. The phone gets byte classes only, never the text.

A Rétegverem-néző: WebGL-síkok, a rétegek saját szövegéből készült részecskerendszerrel, kb. 16 bájtonként egy részecske, Hilbert-görbe mentén, idővonallal és élő eltérés-fénnyel. A telefon csak bájtosztályokat kap, a szöveget sosem.

Asking itKérdezés

CLI and MCP: hybrid search (BM25 over full-text nodes and heading chunks in SQLite, optional embeddings, fused by RRF), node cards, time-respecting paths. The MCP side is read-only and cannot start a build.

CLI és MCP: hibrid keresés (BM25 a csúcsok és címsor-darabok teljes szövegén SQLite-ban, opcionális beágyazásokkal, RRF-fel összefésülve), csúcskártyák, időrendet tartó utak. Az MCP-oldal csak olvas, buildet nem indíthat.

StepLépésLayerRétegReadsMit olvasSignals it raisesJelzései

Privacy is per layer and tested. Client jobs appear as codes only. People appear by role only. The asks' words never leave the PC, and the phone sees byte classes, never bytes.

Az adatvédelem rétegenként adott és tesztelt. Az ügyfélmunkák csak kóddal jelennek meg, az emberek csak szerepkörrel. A kérések szövege sosem hagyja el a PC-t, és a telefon bájtosztályokat lát, bájtokat nem.

Right-sized modelstrengthJó méretű modellerősség

7 · Generality7 · Általánosság

Generic use with databasesÁltalános használat adatbázisokkal

The Stack assumes only three things: each source can be read into nodes and edges, things on different sources share keys, and someone can say which relations count as vertical. Any group of databases meets those three.

A Stack csak három dolgot feltételez: minden forrás csúcsokká és élekké olvasható, a különböző források dolgai közös kulcsokon osztoznak, és valaki meg tudja mondani, mely kapcsolatok számítanak függőlegesnek. Bármely adatbázis-csoport megfelel ennek a háromnak.

In SQL it is three tables and one recursive query, in PostgreSQL or anything like it:

SQL-ben három tábla és egy rekurzív lekérdezés, PostgreSQL-ben vagy bármi hasonlóban:

CREATE TABLE layer (code CHAR(1) PRIMARY KEY, name TEXT, ord INT);
CREATE TABLE node  (id TEXT PRIMARY KEY, layer CHAR(1) REFERENCES layer, kind TEXT,
                    title TEXT, t DATE, state TEXT, props JSONB);
CREATE TABLE edge  (a TEXT REFERENCES node, b TEXT REFERENCES node, rel TEXT, w REAL DEFAULT 1,
                    vertical BOOLEAN GENERATED ALWAYS AS (left(a,1) <> left(b,1)) STORED);

-- the string of one seed: vertical edges, two hops, scores below 0.15 dropped-- egy mag füzére: függőleges élek, két lépés, a 0,15 alatti pontszám kiesik
WITH RECURSIVE s(id, score, depth) AS (
  SELECT :seed, 1.0, 0
  UNION ALL
  SELECT CASE WHEN e.a = s.id THEN e.b ELSE e.a END, s.score * e.w, s.depth + 1
  FROM s JOIN edge e ON (e.a = s.id OR e.b = s.id) AND e.vertical
  WHERE s.depth < 2 AND s.score * e.w >= 0.15)
SELECT n.layer, n.id, max(s.score) FROM s JOIN node n USING (id)
GROUP BY n.layer, n.id ORDER BY n.layer;

Where it sitsHol helyezkedik el

Data catalogs and lineage standards (DataHub, OpenMetadata, OpenLineage) already map tables and jobs as a graph, knowledge graphs join entities across sources, and process mining follows an entity's path through time. What the Stack adds is the layered reading: an entity's coverage across layers taken as its lifecycle state, and drift as the gap between declared and measured state.

Az adatkatalógusok és az adatfolyam-szabványok (DataHub, OpenMetadata, OpenLineage) már gráfként térképezik a táblákat és feladatokat, a tudásgráfok forrásokon át kötik össze az entitásokat, a folyamatbányászat pedig egy entitás útját követi időben. A Stack a rétegzett olvasást teszi hozzá: egy entitás rétegeken átívelő lefedettsége mint életciklus-állapot, és a sodródás mint a bejelentett és a mért állapot közti rés.

What a generic version still needsMi kell még egy általános változathoz

Fuzzy identity resolution (record linkage) with the confidence as edge weight; a set-based join beyond about a million edges; access rules per layer kept as data; and an adapter kit, where each layer declares its nodes, edges, keys and vertical relations.

Elmosódott azonosítás (rekordpárosítás), a bizonyossággal mint élsúllyal; halmazalapú összekapcsolás kb. egymillió él felett; rétegenkénti hozzáférési szabályok adatként; és egy adapterkészlet, ahol minden réteg megadja a csúcsait, éleit, kulcsait és függőleges kapcsolatait.
